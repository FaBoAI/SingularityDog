## GPT-6 Astraと、実物を作りながら開発する

SingularityDogは、**GPT-6 Astraを開発エージェントに据え、人と一緒にロボット犬を作る**FaBoのプロジェクトです。GPT-6 Astraが機構・固定具の設計変更、STLの準備、制御・学習コード、Isaac Labでの実験と結果整理を進めます。人は目標を決め、部品の採寸・調達・印刷・組立を行い、割れや嵌合などの現物情報を返します。

**設計 → シミュレーション・学習 → 動画と数値で評価 → 印刷・現物合わせ → 実機計測 → 改善**を繰り返します。うまくいかなかった試行も記録し、次の設計と学習に反映する開発記録です。

2026-09-29未明時点。**第37回まで評価済み。実機はRS05全12軸を公式FW 0.5.0.13へ更新し、前後2系統のCANで支持台上の保持・停止を確認しています。** 水準器の4脚L字記録とIMU取付補正・ジャイロbiasを反映した最終入力の無出力診断は、初回1＋定常500周期を完走し、全工程最大19.555ms・20ms超過0でした。続く箱支持の学習モデル実出力試験は、開始保持2周期後に指令間隔の上限で中断し、学習目標の送信には到達しませんでした。終了STOPは10軸確認・2軸未確認で、操作者が40VをOffにし、現物異常なしを確認しました。実出力の連続50Hz・自立・歩行は未達です。前進の最終目標は40cm/sです。

**[r6・r7の履歴：9月28日のJetson実測](docs/hardware-native-cycle-20260928.md)：** Type17によるCANとIMUの並列取得は20周期で中央値14.93ms・最大15.01ms。複合返信・実推論・12軸STOP代理送信では、スレッドを事前起動しました。0.8ms間隔と一時的なCPU performanceを維持し、timer slackを1µsへ減らした単独比較100周期では、入力開始→最終ホスト送信は中央値15.96ms・最大16.87ms、最後の返信までは中央値18.74ms・最大19.64msと全周期20ms以内でした。返信後の検査まで含む周期完了は中央値18.97ms・最大22.22ms、2／100周期が20msを超えています。後続の全工程GC比較も各100周期完走しましたが、通常GCの超過とGC時刻は重ならず、GC延期でも初回推論による超過が残りました。CPU・timer・GC設定は元へ復元しています。0.7msは23周期完了後にID9の返信が欠けて中断したため採用していません。通常timer条件の100周期・超過5回の履歴も保存しています。モーター有効化・学習目標送信・立位はまだ行っていません。

**r8・r9の500周期検証：** 準備時GCと周期内の重複コピー削減を追加しました。r8の100周期は全工程最大19.778ms・超過0でしたが、同条件の500周期には8回超過が残りました。r9の公開コードは500周期で最終ホスト送信中央値15.710ms・最大18.004ms、全工程中央値18.740ms・最大21.041ms、10回超過です。別の追加計時で世代1のGCによる遅延とモデル呼出しのCPU時間の増加を確認し、短い成功結果だけで継続50Hzを合格にしていません。GC延期・CPU固定は改善として採用せず、全完了条件と設定復元の証跡を[実測資料](docs/hardware-native-cycle-20260928.md)へ保存しました。

**r13の500周期検証：** 周期内の記録を事前確保した領域へ保存し、詳細JSON化を計測後に移しました。最後の返信後の処理はr11の中央値0.660msから0.185msに短縮しました。一方、全工程は中央値18.792ms・最大21.640msで16回超過し、12回は入力検査・推論を含む区間が5ms以上でした。実機の無駆動診断だけの結果であり、実出力50Hzの合格ではありません。CPUとIMUの設定は復元を確認しました。[条件と原本ハッシュ](docs/hardware-native-cycle-20260928.md)

**r14〜r16の同一起動診断：** 主スレッドだけCPU4へ固定したr14は500周期中、最終ホスト送信の20ms超過0、最後の返信6、全工程9でした。追加時刻を取ったr15は全工程16件の超過を記録し、うち3件が約132周期おきの世代1 GC（約3.1〜3.5ms）と重なりました。計測中だけGCを延期したr16はその停止を除去しましたが、モデル推論が伸びる周期が残り、全工程超過は21件でした。GC延期は採用しません。ワーカー起動・CPU4固定後に30回ウォームアップするr17はモデル呼出しが中央値14.690msへ悪化し、全500周期が20msを超えたため採用しません。次は保存入力で推論内部の候補を比較します。これらはすべて無駆動のSTOP代理診断で、実際の学習目標送信や歩行の20ms達成を示しません。[実測内訳](docs/hardware-native-cycle-20260928.md)

**R20〜R22の更新：** MAXN_SUPERでCPU4固定より前にモデルを10回温め、周期中の自動GCを延期したR21は無駆動500周期の全工程で3回超過しました。固定後に再利用入力バッファを10回準備して状態をリセットするR22は、別起動の無駆動500周期で超過0、周期終了中央値18.018ms・最大19.695msでした。初期3周期のモデル呼出しはR21の4.285／4.994／4.752msからR22の2.875／2.572／2.556msへ短縮しましたが、**別起動なので変更単独の効果とは断定しません**。全軸STOP、CPU・GC設定復元と原本ハッシュを確認済みです。実出力ツールにも同じ初期化順序を明示選択で追加し、ランタイム1814テストを実行しました（1810成功、4スキップ）。このR22記録時点では実出力のJetson計測前でした。後続の⑥は上記のとおり開始保持中に中断しています。[測定と残件](docs/latency-alternatives-20260928.md)

## 実機Deployの状況

**現在地：最終入力の無出力診断501周期は全工程20ms以内。支持付き学習モデル実出力は開始保持中に中断し、再試験が残っています。** ⑥の実モデル計算は3回、現在位置への送信完了は2周期で、学習目標の混合率はまだ0でした。指令間隔の上限と終了STOPの確認待ちを切り分けています。USB物理切断試験は操作者の指示で今回省略しました。初回1周期と現状の開始ジッターを許容する既存条件は維持し、診断の成功を実出力・起立・歩行の成功には置き換えません。

## 現在の課題

| 優先 | 課題 | 次の取り組み |
|---|---|---|
| 1 | 最終入力の記録は反映済み。水準器の絶対精度、加速度ノルム約9%偏差、全可動域には未確定部分が残る | 相対1°の支持付き試験と全域の校正を区別し、限られた試験結果を歩行承認に流用しない |
| 2 | ⑥が指令間隔21msの監視で中断し、終了STOPもID1・2が期限内未確認 | 取得間隔と指令間隔を分けて記録し、停止返信の待ち時間を修正して再確認する |
| 3 | 支持台から四足への荷重移行と学習済み目標送信が未検証 | 箱上の有限保持・停止復帰を照合し、独立した落下受けか補助者を用意して段階的に荷重を移す |
| 4 | 前脚の一部軌道で黄色い部材がカーボンポール固定具に接触 | 接触しない付け根・上脚の経路を現物とCADで確認する |
| 5 | 最新の印刷部品と学習時モデルに差がある | 補強部品・電池配置・質量を現物と照合し、シミュレーションへ反映 |

PLAの割れやナットの入れにくさは設計へ反映済みですが、修正版の印刷・装着・荷重試験の結果をもって解決を判断します。[現在地の詳細](docs/current-status.md)
