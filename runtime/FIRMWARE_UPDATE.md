# RS05 0.5.0.13 更新ツール

対象はRS05、更新前版数`00 05 00 09`、公式`rs05_0.5.0.13.bin`（93,584bytes）のみです。BINのSHA-256は`3a4dfc1e9ad0ff2116b7b876c1fced3b8d23cf705e5d6366e5a286bac3989047`へ固定しています。別機種・別FW・任意ファイルを転送する汎用ツールではありません。

既定は計画の表示だけです。リポジトリ直下から次を実行しても、機器へ接続しません。

```sh
PYTHONPATH=runtime python3 -m singularitydog_hw.rs05_firmware_update
```

実行には、明示した1台のID、安定した前後USBパス、全12台の既知UID、現在のJetson起動ID、1時間以内の完全な事前バックアップとSHA-256、正規BIN、新しい非公開出力先、`--execute-update`が必要です。全台へ自動ループする機能はありません。

## 再試行と期限

| 指定 | 意味 |
|---|---|
| `--start-attempts 1` | 既定。STARTを1回だけ送信 |
| `--start-attempts 3` | STARTの完全無応答だけ最大計3回。完全な17bytes書込み、受信0bytes、残留0、50msの受信静穏が必要 |
| `--start-ack-timeout-seconds 2` | 既定のSTART返信期限。公式参考Pythonの値 |
| `--start-ack-timeout-seconds 3` | 実測した約2.03秒のSTART返信に対応する限定変更。INFO／DATA／ENDの期限は2秒のまま |

任意の部分送信・遅延／不正／重複返信・非ゼロ状態・切断・起動ID変化・取消・全体期限超過は中断します。受信を捨てて再試行可能にする処理はありません。INFO／DATA／ENDの再送、途中再開、別の返信種別への切替はありません。

3回指定時はSTART成功後も50msの静穏を確認します。3秒指定はメーカーが全個体で保証した値ではなく、2026-09-25の実測に基づきます。[公式OTA.py](https://github.com/RobStride/Product_Information/blob/6ad12f50006273b7ea4eea88980f927d97c22f0d/OTA/OTA.py)

## 記録と更新後の判定

更新前に対象バスの6台を同じポートで照合し、停止返信・電圧・版数・静穏を確認します。バックアップは識別と既知7項目であり、全NVMの復元イメージではありません。外部の校正候補は別途保存します。

転送はType11→12→13×11,698→14。各TX、受信生bytes、時刻、ACK、失敗理由、ポート閉鎖とロック解放を保存します。OTA開始後は成功・失敗を問わず通常STOPや設定命令を自動で送信しません。

`TRANSFER_ACK_COMPLETE_PENDING_VERSION`は転送終了のACKを確認した段階です。独立した識別・版数0.5.0.13・STOP mode0／fault0・受信静穏と、読み取れる設定・角度の照合を通過して初めて、その台の更新を確認済みとします。元の転送ログの`version_verified=false`はそのまま保持し、更新後の証拠を別記録にします。

STARTや途中転送で中断した場合、モーターが通常状態かbootloader状態かを推測して通常命令を送りません。前回の失敗状態、電源復旧、UID・版数・停止状態を確認してから、新しい試行として扱います。モーターの有効化、動作目標、原点／ID書換え、工場出荷設定復元、磁気／コギング校正はこのツールに含めません。
