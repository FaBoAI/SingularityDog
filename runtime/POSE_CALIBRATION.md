# ポーズをまとめて記録する関節校正

12関節を1姿勢につきまとめて読み取り、姿勢名・角度一覧・基準との差分を保存します。現在位置へ戻す指令や、モーターの原点変更は行いません。任意の姿勢の記録と、モデル座標に対する関節校正を区別します。

## 今回は目視で進める

担当ユーザーは角度計・治具の使用ではなく「目視確認」を選びました。最初はポーズ名と見た目の基準を決め、P00→立位相当→軽い屈曲→立位相当へ戻す、という順で記録します。立位相当も胴体の支持を続けます。正確な角度が分からない欄は未記入とし、見た目から30°や90°と数値を作りません。

姿勢の合わせ方は、ユーザー指定により**1関節ずつの微小駆動と外付けUSBカメラでの観察**を使います。`rs05_joint_trial`の`jog`を明示選択し、まず確認済みIDの±1°で方向を調べます。[単関節操作の制限](SINGLE_JOINT_TRIAL.md)に従い、操作ごとに停止・位置保存・映像確認を挟みます。自動で全関節を巡回せず、停止後に姿勢が保持される保証も置きません。

1関節を動かして見える回転方向と生角度の増減を照合すれば、方向確認の根拠にできます。モデルの軸との対応も確認してから符号を採用します。原点は目視の仮基準、各ポーズは未校正の候補として保存し、同じ見た目へ戻した際の生角度の差から再現性を確かめます。以下の既知角度を使う校正は、精度を詰める段階の手順です。

## 精度を詰める際の記録順序

| 記録 | 姿勢 | 調べること |
|---|---|---|
| P00 | 現在の支持台上の姿勢 | 生角度の基準を保存。2026-09-20 17:29に取得済み |
| P01 | 支持したまま、膝を軽く曲げた立位相当 | 角度計や治具で実角度が分かる基準姿勢 |
| P02 | P01から対象の1関節だけ、小さく測れる量を変える | ID対応、モデル上の正方向との関係、角度変化 |
| P03 | P01の治具・実角度へ戻す | 再現性、戻り残り、がたつき |
| 後続 | 校正済み可動域内の伏せ・お座り | 動作目標の候補を記録 |

P01は自立試験ではありません。胴体を支持し、脚を動かす前に駆動が無効であることを確認します。膝を伸ばし切る、機械的なストッパーへ押し付ける、抵抗に逆らってPLA部品を曲げる操作を校正基準にしません。動かす作業と読み取りは分け、姿勢が落ち着いてから記録します。

全12関節を毎回保存するので、動かしたつもりの関節以外の変化も比較できます。左右対称に見える姿勢だけでは、関節IDや符号を特定できません。1関節ずつの確認と組み合わせます。

## 原点と正方向を決める条件

関節角の規約は `joint_rad = sign * motor_output_rad + offset_rad` です。実機の関節と最新版モデルの関節軸を照合した後、**モデル座標で角度が分かる異なる2姿勢**を測ります。2点から符号・オフセットの候補を求め、計算に使わなかった3姿勢目で検算します。リンクを水平にしたときの値が、そのままモデルの0°になるとは限りません。

現在はID1〜3の右前脚内の部位対応をユーザーの目視で確認済みです。モデル上の関節名・原点・正方向・可動域は未確定です。ポーズ名や写真だけから値を補完しません。可動域の実測、通信断時の停止、IMU校正は別の項目として残ります。

## 取得と名前付き記録

Jetsonの取得側には検証済みの`20260920-r11`を使います。P00の初回取得時はr9でした。次は例で、保存先は毎回新しくします。`--execute`がなければ計画表示だけです。

```sh
cd runtime  # このリポジトリーのルートから実行
python3 -m singularitydog_hw.joint_snapshot --execute --sweeps 10 \
  --output "$HOME/singularitydog-logs/poses/p01-capture"
```

Type0・17による読み取りだけで、12個の識別と各関節の位置・電流・速度・電圧を取得します。今回の10回測定は約2秒でした。順次読み取りなので、同時刻の全関節状態を保証するものではありません。

取得したディレクトリーをMacの非公開領域へコピーし、`pose_record`で名前を付けます。r11には同じモジュールが入り、Jetsonでも既存ログを処理できます。CANやIMUを開きません。

```sh
cd runtime
python3 -m singularitydog_hw.pose_record \
  --capture /private/path/p01-capture \
  --name p01-supported-reference \
  --note '支持台上。使用した治具、実角度、対象関節を記入' \
  --reference /private/path/p00-capture \
  --output /private/path/poses/p01-supported-reference
```

初回は`--reference`を省略します。`pose.json`と読みやすい`POSE.md`を新規作成し、既存記録は上書きしません。JSONには個体UIDが含まれるため、Git管理外に保存します。ユーザー写真は取り込まず、GitHubへ送信しません。

完了状態、全12個の識別、全サンプル、単位、送信が読み取りだけであること、要求・応答の順序、取得のばらつき、基準とのUID一致・時刻順序を検査します。角度はデコード済みログから再集計し、生受信バイトの再デコードまでは行いません。元のJSON/JSONLのSHA256を保持します。

## 品質と連続性

位置のばらつき0.02rad、速度の最大絶対値0.1rad/s、電流の最大絶対値0.05Aを、再確認を促す**仮の診断基準**にしています。機械的な限界、精度保証、駆動許可ではありません。平均だけで異常値を消さず、全サンプルの最大値も残します。電流0Aは駆動無効の証明には使いません。

基準との差は生角度の引き算です。±πや2πの補正を自動では行いません。モーター電源の再投入・原点設定変更をまたぐ連続性は、同じUID・ホスト時刻だけでは確認できません。電源再投入後は別セッションとして、同じ治具姿勢を再度保存します。

P00は全12個各10点、通信エラー0、角度の最大ばらつき約0.020°でした。速度値はID4で0.104、ID11で0.156、ID12で0.112rad/sとなり仮基準を超えたため、元データを保持した上で`review_required`と記録しています。角度が安定していることと速度値のずれを切り分けてから、校正候補へ採用します。
