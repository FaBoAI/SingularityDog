# 1脚の有限な位置移行・保持試験

`rs05_leg_trial.run_bounded_pose_trial` は、選んだ1脚の3関節に明示的な生角度目標を与え、到達と短時間の保持を評価してから停止する試験用APIです。全12軸の立位制御や学習済み方策の駆動ではありません。従来の `run_leg_trial` の相対5°試験も残しています。

## 入力と経路

- 対象はFR／FL／RR／RLのいずれか1脚。目標はその3つのCAN IDをキーとした `absolute_targets`、単位はradです。
- 保存されたL字基準を自動では読み込みません。原点変更、±1回転補正、目標の分割、自動再試行はありません。
- 個体照合と静止確認後の新しいType2位置を基準とし、各目標が基準±5°以内であることをenable前に検証します。計画・指令の符号化・逸脱監視で同じ基準を使います。
- 4秒のcosine補間、続く名目1秒の保持、合計5秒です。周期50ms、Kp=3、Kd=0.15、フィードフォワードトルク0、最大観測変位7°は既存試験と同じです。

支持台で脚を浮かせた状態と、手離し・即時電源遮断の立会いが前提です。個体・前後バス・起動セッション・静止・電圧・応答鮮度・停止確認は実行側でも検査します。診断計画が生成できただけでは実行許可になりません。

## 到達・保持・停止を別々に記録する

| 判定 | 内容 |
|---|---|
| 到達 | 保持区間の各軸誤差が1°以内。新しい診断用の候補値で、実機の絶対角度精度を保証しない |
| 保持 | 4.00〜4.95秒に予定した20回の新しい3軸観測。各軸の実観測幅0.90秒以上、隣接観測の間隔70ms以内 |
| 鮮度・予定時刻 | 送信batch開始の遅刻20ms以内。要求開始・受信の両方が検査時点から100ms以内。返信完了に送信開始用の20msを誤適用しない |
| 停止 | 識別できた対象すべてへ停止を試み、新しいmode0／fault0応答を確認 |

保持中に未到達・逸脱を検出した場合は、終了時刻まで待たず停止へ進みます。経過時間だけでは保持成功としません。観測幅は実測値を保存し、連続した1.000秒の物理的保持を証明したとは扱いません。

成功時の状態は `BOUNDED_POSE_CANDIDATE_HOLD_RESET_CONFIRMED`。停止は脱力であり、試験後に姿勢を維持する機能ではありません。停止確認が欠けた場合は40Vを遮断する必要があります。ハードウェアwatchdogの物理的な作動時間は引き続き未検証です。

## 検証範囲

オフライン検査では正常追従、未到達、途中の保持喪失、誤った個体／目標、古い値、通信・fault・停止失敗を模擬します。これらの合格を実機試験の成功として数えません。

原点・回転方向・1回転の枝が未確定の保存姿勢へ直接移動させる用途には使えません。近傍目標での追従結果を得た後、校正と可動範囲を確定し、全12軸・両バス共通停止を別途実装します。

## 明示的なゲイン診断

既定の `gain_profile="kp3"` は従来のKp3を使います。別途 `gain_profile="kp4_diagnostic"` を明示した場合だけ、新しい符号化phaseでKp4を使います。Kd・目標幅・時間・到達条件は変えません。既存の相対試験やCLIへ自動的に適用する変更ではありません。

Kp4ではType2トルク値の非有限値／絶対値0.5Nm超を、受信時と次の動作送信前に検出して停止します。この値は現在採用しているプロトコル換算による監視候補であり、物理的なトルク上限や、その閾値の妥当性を保証するものではありません。設定や計画生成から自動でゲインを上げる処理はありません。

9月24日の実機ではKp3版が上脚、Kp4版が付け根の到達不足で中断し、両方とも3軸停止を確認しました。[実機結果と残る課題](../docs/hardware-results-20260924.md)

## 開始姿勢を固定する比較用ガード

`matched_start_positions` に対象3軸の固定参照角（生角度rad）を渡すと、最後の新しい停止中Type2応答と比較します。3軸すべてが参照±0.5°以内であることをenable前、さらに各enable送信前に確認します。要求・応答の鮮度も検査し、一致しなければ駆動を開始しません。0.5°は比較条件の候補値で、絶対角の精度保証ではありません。`matched_start_tolerance_rad` はこの固定値だけを受け付け、値を緩めて通すことはできません。

参照のID・有限性・範囲をI/O前に検査し、入力のコピーを保持します。±2πで近づける処理、実行中に参照を更新する処理、参照へ自動移動する処理はありません。無指定の場合は従来の動作を保ちます。固定参照の個体・起動セッション・USB物理経路・元記録の照合は呼出し側で行います。

付け根を切り分ける次の診断では、ID7・8の目標を参照角に保ち、ID9だけ参照から−4°を目標にします。ID7・8も能動保持するため、3モーターを使う試験です。初期誤差による微小な修正や保持中の実変位も記録し、胴体姿勢・荷重条件まで同一だったとは推定しません。

このガードの追加後、正常一致、0.501°超過、1回転差、Type17と最終Type2の不一致、古い応答、異常・停止失敗を含む関連147テストが通りました。実機r3の完了を意味せず、r1/r2の記録・凍結済み配布物は変更していません。


## 右後付け根だけのKp6診断候補

`gain_profile="rr_hip_kp6_diagnostic"` は、右後脚ID7・8・9だけの明示的な診断候補です。ID7・8のKp4を維持し、ID9のみKp6へ変更します。`position-v2`、3軸の固定開始参照、ID7・8の目標＝参照、ID9の目標＝参照−4°が必須で、不一致は通信前に拒否します。既定profileや相対5°試験、CLIには自動適用しません。

計画には `Kp=null` と `Kp_by_motor` を保存し、各軸の指令・観測にも適用ゲインを記録します。Kd0.15、フィードフォワード0、±5°の指令幅、4秒移行＋名目1秒保持、1°の到達条件、Type2の絶対値0.5Nm監視候補と全軸停止処理は維持します。Kp6の符号化phaseはID9以外を拒否します。監視値は物理的なトルク上限ではありません。

満充電のKp4試験r4でも約1.64°の残差が変わらなかったための切分け候補です。関連138テスト・実行手順31テストが合格し、旧Kp3/Kp4の4条件は凍結版と全結果・通信が一致しました。独立レビュー後にJetsonへ別版r5を配置し、14ファイルと計画表示を確認済みです。その後、実機r5を1回実行。付け根の誤差は約1.64°から1.37°へ減りましたが1°条件で中断し、全3軸停止・操作者の異常なしを確認しました。保持基準は未達です。

## 一定目標の最後1秒を観測するr6

`observation_profile="rr_settling_1s"` は、上の右後Kp4/4/6診断と固定参照・目標を必須とする明示的な観測モードです。既定値 `None` の動作は変えません。ゲイン、4秒移行＋名目1秒、鮮度・異常・指令幅・実変位・トルク監視・全3関節の停止を維持します。

最後1秒だけ、各軸の誤差2°以内かつ最初の完全な保持応答からの悪化0.25°以内で観測します。基準を随時更新する処理や、時間延長・自動再試行はありません。従来の1°到達・保持評価は別途そのまま実行し、観測の完了で合格に置き換えません。

20点・各軸の実観測幅0.90秒以上・停止確認が揃った場合だけ、`RR_SETTLING_OBSERVATION_COMPLETE_RESET_CONFIRMED` を記録します。`settling_observation_completed` と `arrival_candidate_met` / `hold_candidate_met` は独立した項目です。

関連151テストと実行手順33テストが合格。独立レビューでは既定動作6ケース・従来の厳密評価8ケースが凍結r5と一致しました。実機r6は観測と停止を完了しましたが、付け根の誤差は1.374°→1.330°で、1°条件は未達です。操作者は動作と異常なしを確認しました。
