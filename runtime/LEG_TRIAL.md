# 支持台上で脚1本の3関節を同時に確認する

`rs05_leg_trial`は明示選択した脚1本の3関節へ、共通の時間軸で小さな角度目標を送る。
他の脚へは自動で進まない。全脚の起立・歩行・学習済み方策の実行とは別の試験である。

2026-09-21時点で実機の動作・停止を確認したのは右前脚（FR）。明示選択の`position-v2`はFR専用で、個体に結び付いた手動応答のレビュー記録を要求する。他脚の試験成立や全脚への展開を意味しない。[結果](../docs/hardware-results-20260921.md) · [新旧の判定仕様](../docs/rs05-supported-leg-stationarity.md)

| 脚 | 足先側・中央・付け根のCAN ID |
|---|---|
| FR 右前 | 1・2・3 |
| FL 左前 | 4・5・6 |
| RR 右後 | 7・8・9 |
| RL 左後 | 10・11・12 |

現在位置を各関節の基準として、4秒で指定方向へ5°の目標を送り、1秒保持して3関節とも停止する。
CANの送信自体は順次だが、各周期の3つの目標は同じ軌道時刻から計算する。
周期は50ms、Kp3/Kd0.15に固定する。`--directions`は表のID順で、それぞれ`-1`または`1`を明示する。
USB2CANへの送信は、直前の書き込み完了から最低5ms空ける。
待機後に期限・割り込み・故障・フィードバックの鮮度を再確認する。停止指令も間隔を空けるが、
駆動の期限や割り込みによって送信を省略しない。書き込み失敗時も他のIDへの停止を試みる。
この間隔は3軸試験用であり、12軸50Hz制御の通信能力を証明するものではない。
この符号は生のモーター角度に対する符号であり、脚の屈伸方向やモデル軸を自動決定しない。
保存したL字姿勢や原点へ移動させる機能はない。

有効化する前に3台すべての個体情報、停止応答、制御モード0、位置の符号化一致、電流・電圧、
角度符号化の余裕、揮発CAN timeoutの4000ticks読戻しを確認する。
設定後に位置と無効状態の応答を再取得する。固定2秒・21点の全観測から位置幅・位置傾き・速度RMSを評価し、
3台すべてが条件を満たす場合だけ有効化へ進む。各有効化直前にも最後の観測の一致と鮮度を再確認する。
観測の選別や自動再試行は行わない。[静止判定の仕様と限界](../docs/rs05-supported-leg-stationarity.md)を参照。
3台の有効化と中立応答が揃ってから動作を開始する。
通信口と受信パーサーは1つを共有し、待ち受け中も3台すべての異常応答を監視する。

いずれかの関節で応答の古さ100ms超、開始位置からの偏位7°超、速度0.5rad/s超、温度50℃以上、
故障、通信・周期異常、操作者の中断があれば、残りの軌道を中止する。
終了処理では応答を待つ前に、識別済みの各関節へ停止を試みる。
1台の送信・読み取り・記録に失敗しても、他の関節への停止送信を省略しない。
全3台の新しい停止状態0・故障ビット0を確認できた場合だけ、正常停止として扱う。

これは支持台に載せて脚を自由に動かせ、操作者がモーター電源をすぐ切れる状態で使う。
使用する方向と全経路の周辺空間は、試験前に実機で確認する。
モデル計算の経路は校正候補に依存し、実際の床・支持台・ケーブルとの離隔の証明にはならない。
終了後は脱力するため、目標角度を保持し続けない。
ゲインや振幅の自動増加、再有効化、次の脚への自動移行はない。

実行なしの計画表示が既定。`--expected-uids`には、直前の非公開記録から作った
選択3台または全12台のID→個体情報のJSONを渡す。
`--execute --supported --operator-power-cut-ready`を付けた場合だけ実機操作へ進む。
引数は現場確認を代行しない。試験の前後には別途`joint_snapshot`で全12台を照合する。
生ログ・個体情報・写真・動画はGit管理外に保存する。

6秒のコマンド予算、公称200msの通信timeout、速度・偏位の監視は、物理停止遅延や総トルクの保証ではない。
電源投入をまたぐ原点の連続性、モデルの正方向、可動域、学習済み方策の駆動許可は変更しない。
