# 支持台上での単関節試験

脚1本の3関節を同じ時間軸で動かす別プログラムは[脚単位の試験](LEG_TRIAL.md)を参照。
この単関節プログラムの対象は引き続き1台だけである。

対象はRS05のID1〜12から`--motor-id`で明示選択した1台のみです。既定はID1（右前脚の足先側）です。自動で次の関節へ進む機能はありません。自立・歩行・全関節一斉駆動には使いません。支持台上で4脚を自由に動ける状態とし、担当者が40Vのモーター電源をすぐ切れる位置にいる場合に限ります。

`joint_snapshot`は全12個の識別と位置・電流・速度・電圧を読むだけです。`joint_observation`は保存済みの前後ログを比較するだけです。比較結果は対応関節の候補であり、原点・回転方向・可動域を自動承認しません。

`rs05_joint_trial`は別系統の監督下試験です。初期停止、ID一致、run_mode0、Type17とType2の位置一致、電流・電圧を検査し、停止状態でゼロゲインの応答を確認します。選択IDのCAN timeoutを揮発設定で200msへ変更し、読み戻しが4000ticksと一致したときだけEnableへ進みます。保存・ゼロ設定・故障クリア・他IDの駆動は行いません。

Enable直後にゼロゲインを再送します。現在位置を基準として最大+1°、3秒で往復する軌道をKp0.5、Kd0.02で送ります。動かなくてもゲインを上げません。全受信Type2と選択IDのType21故障報告を検査し、位置逸脱3°、速度0.5rad/s、温度50℃、応答期限・通信異常・シグナルで打ち切ります。これらは初回試験用の選択値で、メーカーの物理上限ではありません。

初回結果と現物の観察を確認したあと、別の試験として`--gain-profile step2`を明示選択できます。これはKp5、Kd0.05に固定し、角度・時間・中断条件は初回と同じです。プログラムが初回から自動移行することはありません。公称1°誤差でのP項は約0.087Nmですが、総トルクの保証上限ではありません。

1°試験で動きが小さく目視で関節を識別できない場合に備え、明示選択の`visible`も設けています。最大+3°、Kp3、Kd0.15、位置逸脱の中断値5°とし、往復3秒・速度監視0.5rad/s・コマンド予算4秒は維持します。振幅を広げる一方で比例ゲインを下げ、減衰を増やした比較試験です。この設定も現物の観察後に別試験として選び、自動移行しません。

目視で姿勢を合わせる操作には`--trajectory-kind jog --gain-profile step2 --direction 1`（または`-1`）を明示指定します。直前に読んだ現在位置から、2秒で±1°へ滑らかに動かす目標を送り、1秒だけその目標を送り続けてから停止します。Kp5/Kd0.05、逸脱3°・速度0.5rad/s・総時間3秒の監視は維持します。`initial`や`visible`との組み合わせ、任意の移動角度・保持時間は受け付けません。既定の`return`は従来どおり往復です。

1°の試験後に操作者が5°の移動を明示指定した場合は、別設定の`--trajectory-kind jog --gain-profile step5`を使用できます。4秒で現在位置から±5°へ移動し、1秒保持して停止します。Kp3/Kd0.15、位置逸脱7°、速度監視0.5rad/s、総時間5秒、有効化前からのコマンド予算6秒に固定します。`step5`と`return`は組み合わせられず、既存設定から自動移行しません。5°の誤差での公称P項は約0.262Nmとなり、Kpを下げても1°試験より総トルクが小さいとは限りません。7°は実測変位の打切り条件で、機械的可動域や停止後の位置を保証する値ではありません。

`jog`の符号はモーターの生角度に対する方向で、機体関節の正方向や屈曲方向を示すものではありません。保存したP00の絶対角度を再生せず、その場で取得した位置を中心にします。1回ごとに停止・カメラ観察・全12関節の再取得を行い、P00からの累積変化も確認してから次の操作を選びます。小さな移動を繰り返せば累積可動量は増えるため、1回の逸脱制限を機械的可動域と扱いません。

最後のType4停止で駆動は無効となり、その後は能動的に姿勢を保持しません。重力やがたで位置が変わり得るため、目標の終点、停止直前の実測位置、停止後の読み取りを別々に記録します。未達やオーバーシュートによる自動再試行・ゲイン変更はありません。カメラは観察・記録用で、独立した緊急停止装置としては扱いません。

有効化前から4秒（`step5`のみ6秒）のコマンド予算を設け、それ以降は新しいType1/3を送信しません。終了処理は通信エラー後もType4停止を試みます。実際の停止時刻にはシリアル転送・デバイス処理の遅延が加わり、その上限は未検証です。新しい停止応答の対応付けを保証できない場合は停止未確認とします。故障報告は後続の正常応答で取り消しません。

注意点：

- 速度目標0やフィードフォワードトルク0は、速度・総トルクの上限を意味しません。uint16変換ではゼロにも微小な量子化誤差があります。
- 無効状態の目標がEnable後に保持される保証は確認できていません。支持と物理電源遮断は必須です。
- timeoutの読戻しは通信断時の実停止試験ではありません。設定は保存せず、試験後も200msのまま残します。
- Type2とType17の位置が一致しない場合、±π等の折返しを推測して駆動を継続しません。
- `SafetyGuard`による歩行運用の認定・IMU校正・12関節の校正を代替しません。

実行なしが既定で、`--execute`に加えて`--supported`と`--operator-power-cut-ready`が必要です。`--expected-uid`には直前の非公開診断ログから選択IDのUIDを指定します。コマンド引数は、現場確認を代行するものではありません。出力はGit管理外の新しいフォルダーへ保存します。写真・動画・UIDを公開リポジトリーへ追加しないでください。
