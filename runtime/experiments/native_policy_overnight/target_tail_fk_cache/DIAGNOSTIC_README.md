# Explicit FK candidate in a separate STOP diagnostic

The sparse baseline kit need not contain the saved-input replay helper. The
separate child binds that helper from the selected diagnostic manifest's exact
report-backed reference before importing the frozen FK generator, using its
fixed source SHA and qualified module name. It never adds the saved-source
directory to a search path. The loader checks the executing helper bytes and
the child rechecks them during cleanup. PLAN imports this pure helper without
Torch or native loading. The sparse-package regression uses a fresh isolated
interpreter and synthetic PLAN artifact fixtures; target artifact loading and
ABI checks remain separate.

Registered TorchScript methods are inspected through `_c._get_method(name)`.
Python attributes such as a scripted Sequential's `__len__` can be ordinary
wrappers without `.code`; they do not replace the registered-method comparison.

These new modules prepare a separate diagnostic. They do not change the ordinary
scalar loader, benchmark, saved-input candidate, or an active-controller profile.
The original `collect` function, observer calls, waits, guards, twenty millisecond
period, native deadlines, correction, and warmup/reset order are unchanged.

`diagnostic_generate.derive()` requires the exact frozen benchmark source and
checks inverse full bytes and AST. Only `main` changes. The generated module
requires explicit candidate selection and accepts five or 501 disabled V3 STOP
proxy cycles at a 900 microsecond request gap. It cannot select Type1 targets or
motor enable. STOP writes still change motor state; execution requires the usual
independent support, current pose/power checks and attended root workflow.

The artifact document uses schema
`singularitydog.fk-cache-stop-diagnostic-artifact.v1` and the unapproved status
`PREPARED_DIAGNOSTIC_ARTIFACT_NOT_ACTIVE_APPROVAL`. Its eleven references bind the
file-only comparison report and independent audit, source manifest, original
scalar/baseline manifests, saved501 report/records/raw audit, replay helper, and
candidate model/library. Separate maps pin the protected24 sources, four generated
sources, and five integration sources. Every referenced file is bounded, regular,
SHA checked, and rechecked. Existing first/FK candidate files are unchanged.

The selected loader registers the original scalar/projection dependencies through
the unchanged verified scalar loader. It then loads only the pinned FK library
and model, independently resets both models, and checks method code, cached
aliases, disjoint state storage, finite metadata and exact state bytes including
signed zero. No compilation occurs. A fresh process is required for operator
registration. The returned provenance identifies the FK artifact separately from
the original scalar dependency. PLAN performs file checks without importing Torch
or loading a model/native library.

The FK target is an opaque C++ operator in the visible forward graph. Its scalar
and projection dispatcher calls are authenticated by the protected C++ source
and library-source proof. They are not required to appear in that forward graph.
The original exported helper methods remain subject to exact code comparison.

The source generator creates a fresh private bundle. The child verifies the
