# 診断処理のネイティブ化実験 r1

CPython 3.12 / Linux aarch64 の Jetson 向けに検証した、イベントコピーと
起動 ID 確認の実験用ソースです。既存コントローラーの既定実装は変更しません。
実験ハーネスが明示的に import・選択した場合だけ使用します。
実機の制御出力や連続 50 Hz 動作を承認するものではありません。

このディレクトリには C/C++ ソース、Python アダプター、ビルドスクリプトだけを
保存しています。機体 ID、キャリブレーション、写真、非公開キャプチャ、モデル、
ターゲットの実行バイナリは含めていません。生成される `.so` とビルド記録は
`.gitignore` で除外しており、コミット対象にしません。

## ビルド

検証対象は CPython 3.12.3、Linux aarch64、GCC/G++ 13.3.0 です。
実行する Python と一致する開発ヘッダー、C11 コンパイラー、C++17 コンパイラーが
必要です。`Python.h` がない場合は、管理者が適切な Python 開発ヘッダーを用意して
ください。スクリプトは OS パッケージを自動インストールせず、ネットワークにも
接続しません。ビルド自体に setuptools などの外部 Python パッケージは不要です。

リポジトリのルートから実行します。

```sh
cd runtime/experiments/native_diagnostic_r1
python3 build_native_event_copy.py
CXX=g++ python3 build_native_boot_guard.py
```

それぞれ `_event_snapshot_native.c` と `native_boot_guard.cpp` を同じディレクトリ
から読み、実行中 Python の ABI 名を持つ `_event_snapshot_native*.so` と
`_native_boot_guard*.so` を生成します。異なる Python バージョンや Mac のバイナリを
Jetson に流用せず、その環境でビルドしてください。両スクリプトはコンパイル内容を
表示し、起動 ID 側は `build-record.json` にソース・バイナリの SHA-256 も保存します。

## 明示的な読み込み

イベントコピーは、このディレクトリを import 検索対象にした実験コードから
`from event_snapshot import snapshot_event` で選択します。既存の
`singularitydog_hw.event_snapshot` をこの保存作業で置換・変更することはありません。
拡張モジュールがない、または ABI が異なる場合は import が失敗します。
Python 実装への暗黙の切り替えはありません。

起動 ID 側は `native_guard.NativeBootIdentityGuard` を実験用ガードの生成箇所で
明示的に選択します。このラッパーは既存の `singularitydog_hw` を必要とします。
上記ディレクトリから `PYTHONPATH=../..` を設定すると、このリポジトリの runtime
パッケージを参照できます。ガードの生成は既存の procfs パスを開くため、単なる
import と生成・実行を区別してください。実験全体では開始前にソースと拡張
バイナリのハッシュを確認し、既存の外部監視・停止処理を維持します。

## イベントコピーの契約

`snapshot_event(value, *, max_depth=24, max_nodes=20000, max_bytes=1048576)` は、
厳密に組み込み型の dict/list/tuple/str/int/float/bool/None だけを受け付けます。
辞書のキーは組み込み str、浮動小数点数は有限値に限定します。サブクラスや未知の
型を拒否し、その変換・コピーフックを呼び出しません。

可変の子孫は新しく所有し、同じコンテナーへの繰り返し参照も出現ごとに独立して
コピーします。循環参照は拒否し、tuple の型、辞書の順序、非可変スカラーの同一性を
保ちます。深さ・ノード数・保守的な JSON バイト数の計算と拒否順序は検証済みの
Python 実装と同じです。整数カウンターが C の範囲を超えると PyLong へ昇格します。
走査中は GIL を保持します。コピー対象は呼び出し中に変更しない前提です。

CPython 3.8～3.13 の整数ビット数には CPython 固有の `_PyLong_NumBits` を使います。
安定 ABI や PyPy 互換は保証しません。ソース中の 3.14 以降向け分岐は今回の
ターゲット検証には含まれません。

## 起動 ID 確認の契約

既存ガードの初期化、ファイル記述子の所有権、Python ロック、close を継承し、
確認箇所と確認頻度を維持します。各確認で先頭オフセットから最大 80 バイトを
新しく pread し、bytes.strip() と同じ ASCII 空白処理をして期待値と比較します。
確認結果のキャッシュはありません。実行用ラッパーには任意パスの引数がなく、
従来と同じ Linux procfs の起動 ID を使います。

ネイティブ確認は GIL を保持します。EINTR による割り込み時は各システムコールの
試行回数を最大 8 回に制限し、上限到達時は成功扱いにせずエラーにします。
バイト数・再試行回数の上限は、システムコール自体の所要時間のハード上限では
ありません。既存のキャンセル、期限、終了処理、外部 watchdog を省略できません。
GIL を保持することでスレッドの実行タイミングも変わるため、全体の時間は実測が
必要です。

- イベントコピー: 16 テスト、23,668 件の差分比較が成功。
- 参照実装を使う既存テスト: 116 件中 114 件成功、過去の非公開キャプチャがない
  2 件はスキップ。

- 別の Mac 統合テストコピー: 119 件中 118 件成功、任意キャプチャの 1 件はスキップ。

## 追加候補：Type2返信検査のC++化

`native_input_validation.cpp` と `native_fast_policy_inputs.py` は、既存の
`fast_policy_inputs.prepare_cycle` と同じ検査を行う追加候補です。
`python3 build_native_input_validation.py` で構築し、実験側から
`native_fast_policy_inputs.prepare_cycle` を明示選択します。既存runtimeの既定値は
変更しません。上記イベントコピーの拡張とruntimeパッケージも必要です。

12台の原本フレーム、型、フラグ、raw16換算、時刻順序をC++で検査します。
所有コピー、IMU検査、3種類の証拠ハッシュ、スナップショットの鮮度再検査は
維持します。浮動小数点の演算順を保持し、fast-mathは使いません。

Jetsonで67,568件の差分照合（65,536通りの全raw16値を含む）に成功しました。
追加の549件の独立確認も一致。保存入力3件を15標本×20反復で交互比較し、
CPU時間中央値は1.212msから0.658msへ短縮しました。この値はschedutil条件の
入力準備だけの比較で、全工程から単純に差し引くものではありません。
組込み版は120件中118成功・過去記録不足2件skip、監督・復元処理は66件成功。
この追加候補による全工程は20.135871 / 20.063117 / 19.785404msでした。
1回は20ms未満ですが、全回達成と連続50Hz制御は未確認です。
詳細は上記測定レポートを参照してください。

公開用の合成データ検証は、拡張ビルド後にこのディレクトリで
`python3 -m unittest test_native_input_validation -v` を実行します。
Mac CPython 3.13では34件（参照実装の契約、同契約のC++版、差分比較）を確認しました。
実機固有のキャプチャは不要です。
