# 実験を継続し、成果の出所を保つ

[実験の運用](references/operations.md) と [公開範囲](../../docs/publication-scope.md) を読む。接続情報や第三者の部品入力は利用者の環境から取得し、公開ファイルへ保存しない。

1. 再接続時は既存のジョブ状態、プロセス、GPU の使用者、終了記録を読み、起動済みなら重複起動しない。
2. 実験ソースと入力を `tools/artifact_manifest.py` で固定する。結果から、使用した物理・制御・初期重み・設定・ソースへ辿れるようにする。
3. 有限の更新数、所要時間上限、保存先、成功時に必要な終了記録を含む明示的な起動要求を作る。`tools/bounded_job.py` はその要求をローカル Linux/macOS 上で実行できる。SSH や環境構築は別途用意する。
4. フレームワークの終了コードだけで成功にしない。予定更新数、最終反復、重みの存在・固定ハッシュ、必要な終了記録を検証する。
5. 正常終了後、実際に存在する最終重みを出力・評価へ引き渡す。監視は状態変化・完了・失敗だけを通知し、設定を変えない自動再試行をしない。
6. 引継ぎには現在の状態、最後に確認した時刻、完了したもの、残り、次の具体的な操作を残す。公開版では実行環境の識別情報を除き、測定値を明示的に選ぶ。

公開更新では `RELEASE_FILES.json` をレビューし、`tools/check_publication.py` を実行する。既存の作業フォルダを丸ごと追加しない。

改善の連続記録には [ループ比較の手順](../../docs/improvement-loops.md) を使う。各実験を新しい ID で登録し、変更・状態・実測・動画を結び付ける。新しい動画がまだない場合も、その状態を比較画面に残す。
