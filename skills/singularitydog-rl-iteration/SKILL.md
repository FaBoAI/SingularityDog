# 観測できる実験単位で学習を改善する

[現在地](../../docs/current-status.md) を確認し、[学習の契約と診断](references/training-contract.md) から対象の部分を読む。

- 目標速度と指令速度を分ける。速度の報酬が増えても、実際に必要方向へ移動したかは別評価にする。
- 物理モデル、制御周期、関節順、観測スケール、指令分布、初期化、報酬の定義と重みを実験記録へ固定する。
- actor の入力は実機で取得・推定できるものに限定する。シミュレータの真値を critic に使うなら分離して明記する。
- 参照運動に学習した残差を加える方式なら、その構成と参照の状態を開示する。学習済み重みだけで全動作が決まると説明しない。
- GPU を使う前に CPU の整合検査と有限の API・物理チェックを行う。未学習の転倒と数値・インターフェース異常を分ける。
- 異常は駆動計算の周期で記録する。出力値、入力速度、接触、リセットを保存し、ガードを緩めて成功にしない。
- 更新数を限定して試し、実測が仮説を支持したら次の段階へ進む。同じ設定の無制限な再試行はしない。

Isaac Lab の実環境で API とバージョンを確認する。公開パッケージは環境固有の学習コードを同梱しない。既存のローカル実装を使うときも、ソースの出自と実行条件を独立して管理する。
