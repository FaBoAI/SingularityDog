# STOP代理診断の周期前方策warmup比較

R14の現起動500周期で、最初の6回の`observer.consume()`が約5.3〜6.6ms、以降の通常値が約3.8msという観測があった。その後の保存入力だけを使う別プロセス比較では、10回の合成warmupをCPU4固定**前**に行うとモデル呼出し中央値が約2.6ms、固定**後**に行うと約15.0msだった。後者ではTorchの補助スレッド5本もCPU4に固定されていた。これは実機の全工程20msを証明する結果ではないが、warmup位置を決める根拠になる。

`native_pipeline_benchmark.py`の明示オプション`--pre-cycle-policy-warmup-calls 10..100`は、最大500周期の方策推論付きSTOP代理診断だけで使用できる。指定した場合、既存位置での10回warmupを行わず、3ワーカー起動後、任意の`--main-thread-cpu`固定**前**に指定回数の**合成入力**で方策を呼ぶ。完了後にobserverを1回だけresetし、主スレッドだけを固定してワーカーが固定されていないことを確認する。warmup時間と固定確認は周期計時に含めず、その終了後に最初のreleaseと全体期限を設定する。UID照合、IMU開始、STOP代理のみの出力、安全判定、CPU設定の復元は従来どおりである。

オプション未指定時は従来の10回warmup位置・回数を維持する。実機の再比較では、未指定と指定10回を同一条件で別試行し、500周期全体の推論分布、最後のSTOP返信、周期完了、超過数を確認する。保存入力で速くても、実機の短縮量・20ms達成・実出力の有効性は未測定である。既存R14/R15キットの内容や過去結果を変更しない。
