## 時刻と合格条件

| 項目 | 定義 |
|---|---|
| `output_reply_end_ns` | 今回の出力12要求に対する最後のネイティブ受信時刻 |
| `output_exchange_return_ns` | 両バス所有スレッドの処理を主スレッドが受け取った時刻 |
| `end_ns` / `iteration_ms` | 返信デコード、関節・速度・トルク・温度等の照合、周期の指標作成、最終ガードまでを含む完了時刻／周期開始からの時間 |
| `post_output_processing_ms` | 所有スレッドから戻った後、上記の検査・指標作成に要した時間 |
| `oldest_input_to_final_host_write_ms` | 今回使った最古入力の取得開始→最後のホストwrite復帰。CAN線上の送信完了時刻ではない |
| 入力の古さ | 最古入力取得開始→検査済み周期完了。地上試験の評価器が生時刻から再計算する |
| `max_release_interval_ms` | 連続する周期の`begin_ns`間隔の最大値。処理時間とは別に評価する |

今回、返信到着時点だけを周期終了にしていた集計を修正した。最後のゲインゼロ周期でも、返信後の検査が締切を越えれば成功にしない。配列やJSONのコピーは全バス停止後に行う。

**処理時間と入力→最終ホスト送信は各20ms以内、開始間隔は既存の起床余裕1msを含め21ms以内**として分けて検査する。21msは計算時間を延長する許可ではない。評価器は開始間隔を生の`begin_ns`から再計算し、`release_intervals_over_21ms`を記録する。各周期が10msで終わっていても、一度30ms空いた立位記録には`actual_controller_20ms_pass`を付けない。歩行段階も同じ間隔条件を必要とする。これらの短時間検査でも`full_controller_50Hz_verified`は自動的に真にしない。
