# 40 V再投入後の角度枝の比較候補

40 VのOff/Onをまたいで、同じ実物姿勢でもRS05の`0x7019`生角が約360°ずれる場合がある。今回のID3では、再投入後の読取り専用記録の**直接差が+361.307°**だった。操作者はID3出力部が物理的に1回転していないと確認している。この条件なら、比較用に限ってID3の新しい生角から`2π` radを引き、残る約+1.307°を姿勢差の候補として表示できる。両記録の校正原点・符号が確定したことや、駆動可能になったことは意味しない。

[RS05公式マニュアル](https://github.com/RobStride/Product_Information/blob/main/Product%20Literature/RS05/RS05User%20Manual260713.pdf)は14-bit単回転絶対エンコーダを記載し、`zero_sta=0`なら通電開始時の角度範囲を`0..2π`、`zero_sta=1`なら`−π..π`と説明している。通電をまたぐ多回転数の永続性は明記していない。今回の差は角度枝の再初期化と整合するが、通電前後で脚の実姿勢が少し異なるため、原因を断定はしない。`zero_sta`の変更・機械ゼロの書込みはこの比較に不要で、実施していない。

同じ40 V投入後にID3だけを読取り専用で再確認したところ、Type0のUIDは基準記録と一致し、`0x7029 zero_sta=0`、`0x7019 mechPos=6.26289749 rad`だった。これは再投入直後の範囲`0..2π`内で、前記の`6.26279831 rad`から約0.0057°しか変わっていない。Type0/Type17の要求以外は送っていない。これは枝の解釈を支持する追加資料だが、停止返信や物理姿勢の測定には代わらない。

[保存済みの再投入後診断](../runtime/singularitydog_hw/post_charge_box_pose_check.py)は、現在も全12軸の生角と直接差をそのまま残す。[比較専用ヘルパー](../runtime/singularitydog_hw/angle_branch_comparison.py)は別の結果を作り、元の角度・校正値・モーター指令値を書き換えない。ID3以外に実物姿勢が変わった軸は、個別の非回転証拠がない限り枝補正の対象にしない。

ヘルパーは次を必須にする。

- 前後それぞれの12軸生角、それぞれの起動・モーター電源区間で新規に読んだ12個のUID、読み取り元のハッシュ。12個のUIDとID対応は前後で同じでなければならない。
- Jetson起動IDとは別に識別された、異なるモーター電源区間。40 VのOff/Onを確認した独立記録と、比較対象の軸ごとに実物の1回転がなかったという明示的な観察。
- 対象軸の直接差が`0`または`±2π`から10°以内で、枝差が高々1回転であること。対象外の軸は生角を保持する。後続の同一区間読取りで対象軸に10°超の単発段差や基準から10°超のずれがあれば、その比較セッションを中断する。

この条件は**保存記録の静止姿勢比較**に限る。外部の物理観察が誤っていれば、生角だけでは実際の1回転とエンコーダの枝切替を識別できない。現在の再投入後記録には独立したモーター電源区間IDと物理非回転証拠の機械可読な結び付けがないため、このヘルパーへそのまま渡して自動承認しない。記録に紐付く証拠を照合してから、オフラインの比較結果として扱う。

再投入後診断の`run_mode=0`は制御モードの値であり、STOP返信による脱力証明ではない。実際に記録された電流ゼロと、ツールが駆動命令を送らなかった事実を、モーターの停止状態の独立検証と取り違えない。

学習済み方策の**無出力診断**の観測値を作る箇所は[`policy_observer.py`](../runtime/singularitydog_hw/policy_observer.py)の`StatefulPolicyObserver._inputs`で、`q = sign * raw + offset`の直後に関節範囲を検査する。現在はレビュー済み`StaticBranchComparison`を明示して渡した場合だけ、電源区間・UID・取得記録を各診断周期で照合し、対象軸の観測値に`sign * (raw - k * 2π) + offset`を適用できる。通常経路、関節範囲ゲート、モーター出力禁止は維持した。数式上は対象軸だけ`b_new = b_old - sign * k * 2π`という観測オフセット候補と等価である。実機のモーター指令経路には接続していない。校正・物理姿勢・新しい電源区間の証拠が揃うまで実機の駆動開始判定には使わない。

[`offline_box_rise_candidate.py`](../tools/offline_box_rise_candidate.py)の生角目標は、同じ電源区間で読み直した現在枝の生角と有限差分から作る必要がある。旧区間の生角目標を`±2π`して再利用する根拠にはならない。

次の40 V投入から運用へつなぐ手順は、(1)箱で支えた静止姿勢で投入前のUID・生角・STOP返信を保存、(2)Off/Onの時刻を独立した電源区間IDとして記録し、投入後にUID・生角・`zero_sta`・STOP返信を読み直す、(3)疑わしい軸だけ実物の一回転がなかったことを確認して`k∈{-1,0,+1}`を決める、(4)生角を保持したまま無出力の方策観測と関節範囲を照合、(5)駆動する場合は**新しい生角枝の現在値**から目標と追従幅を作る、の順である。角度だけで一意に枝を選べない場合は姿勢の再照合が必要。各周期に無条件で`mod 2π`をかける方式は、実際の一回転や飛び値を隠すので使わない。

将来、原点・回転方向と機械的な可動範囲を実測で確定できれば、その範囲が一周より狭い関節は新しいUID・生角から**可動範囲に入る枝が一つだけ**という条件でも自動選択できる。ただし現在の校正候補とURDF範囲だけではその物理保証が済んでいないため、現機体の自動選択条件には採用しない。

数値の補足：以前のL字記録値`−0.043743 rad`と現在の`6.262798 rad`をそのまま引くと、`2π`を除いた残差は**+1.33818°**になる。上記の+1.307°は別の基準姿勢を持つ再投入後の直接差に対する値であり、基準記録を混ぜて計算しない。
