# 9月24日の実機試験計画

**主目標は、支持台上で指定姿勢へ動かし、短時間保持して停止すること。条件が揃えば、支持補助付き立位から学習済みモデルによる短い低速前進へ進みます。**

9月23日時点では、全12軸の絶対姿勢移行・保持制御と、2系統CANを使ったモデルの実時間接続が未完成です。本書の実装項目は予定であり、配置済み・試験済みの機能ではありません。開発時間と、操作者に立ち会っていただく試験時間を分けます。

[前日の実機レポート](hardware-results-20260923.md) · [Deployの残作業](deployment-next-steps-20260923.md)

## 1. 実機試験前に開発側で済ませること

| 順 | 開発するもの | 実機へ持ち込む前の完了条件 | 工数の目安 |
|---|---|---|---|
| A | 最新L字基準を使う角度変換と、1脚の有限な移行・保持・停止 | 個体・関節順・符号・原点と逆変換が一致。現在位置から目標までの経路と可動範囲を検査。到達誤差・速度・電流・時間の限界を事前固定し、超過時に終了する | 2〜4時間 |
| B | 前後2系統、全12軸の保持・共通停止 | バスごとに1処理が所有。片側の通信断・古い観測・fault・プロセス終了で両側の指令を打ち切り、全対象の停止を確認。時間切れ後に保持が残らない | Aに追加2〜4時間 |
| C | 2系統＋IMU＋モデルの無出力診断 | 原取得時刻・観測の古さ・推論時間を保存。関節変換、姿勢、内部状態、出力制限を接続し、有限区間で連続実行を検証 | A/Bと並行。周期問題の切分け後に再見積り |
| D | 当日の一括実行と結果表示 | 起動照合→選んだ有限試験→停止確認→結果保存を一続きにする。前の合格段階を再利用し、中断理由と次の1手を表示 | A/Bに含む |

A/Bの**合計4〜8時間は新規実装・検証の工数見積り**です。既存の通信・個体照合・排他・ログ処理を再利用しますが、追従や再通電後の角度に新しい問題が出れば延びます。Cの完成や歩行までを、この時間内に保証するものではありません。

試験前には、片側欠落、古い値、位置の飛び、未到達、停止返信の欠落を模擬した検査とコードレビューを終えます。角度や停止を扱う部分の実装が終わっていない場合は、操作者を待たせて現場で書き始めず、準備状況を先に伝えます。

## 2. 操作者側の準備

- Jetson用・Makita用の両バッテリーを充電。前後のUSB接続位置を固定しておく。
- 胴体を支持台に載せ、動かす脚が床・台に触れない状態を用意。初回は接地させない。
- 過去に破損した固定部を含め、PLA部材・ねじ・配線に干渉や緩みがないか確認。
- 試験中は手を脚から離し、40VをすぐOffにできる位置で立ち会う。カメラは機体全体が見えると確認しやすい。

最初から4脚を同時にL字へ手で保持する必要はありません。昨日の4脚記録を使用し、再照合が必要な関節だけ短時間合わせます。

## 3. 当日の進め方

時間はA/Bの実装・事前検査が済んでいる場合の、各段階の所要時間の目安です。未知の不具合を直す時間は含めません。

| 段階 | 立会い時間の目安 | 実施内容 | 次へ進む条件 |
|---|---|---|---|
| ① 起動確認 | 10〜15分 | 12個体・前後バス・電圧・現在角度を照合。最新L字基準と電源再投入後の角度を確認 | 対応が一意で、静止・電圧・通信の条件が成立。不明な関節だけ再確認 |
| ② 1脚の移行・保持 | 20〜35分 | 現在姿勢に近い目標へ小区間ずつ移り、短時間保持して停止。追従不足の指令・位置・速度・電流を比較 | 事前に定めた到達誤差と各制限を満たし、目視・停止確認も完了 |
| ③ 4脚の姿勢保持 | 追加20〜40分 | 支持台上で立位用の4脚姿勢へ有限移行。全12軸の保持と両バス共通停止を確認 | 専用制御周期と観測鮮度が成立し、全脚が追従。停止・通信断時の動作も確認 |
| ④ モデル接続と接地 | 追加30〜60分以上・条件付き | 連続無出力推論→支持付き方策駆動→支持補助付き接地→短い低速直進→停止 | 下記のモデル条件と、立位・実荷重・停止の確認がすべて成立 |

**支持台上の4脚保持まで約50〜90分、モデルを含めると約80〜150分以上**を目安にします。歩行の完了時刻はまだ約束できません。②までの達成でも「指定位置へ動かし、保持できた」という明確な前進として記録します。

L字は校正用の基準で、接地して立つための姿勢とは分けます。③では運動学と実機の可動範囲から確認した立位用の目標を使用します。

## 4. モデル歩行へ進むために残る条件

| 条件 | 現在の未達 | 対応 |
|---|---|---|
| 角度の整合 | 旧候補での保存姿勢チェックは付け根3軸が範囲外。ライブ診断も関節範囲で中断。最終L字基準と旧値には約1回転の差がある | 最新基準と現在姿勢を照合。角度の切詰めや無条件の±360°補正で通過させない |
| 周期と入力の鮮度 | CANのみでも取得幅中央値29.744ms・最大36.801ms | バス別・並列の処理時間と開始差を分離。IMU・推論・出力を含む20ms周期を検証 |
| IMU姿勢 | yaw・動的応答・加速度約9%偏差の扱いが未完了 | 固定位置のまま、必要な向き確認と連続姿勢推定を実測検証 |
| モデルからモーターへの変換 | 状態保持の合成入力検証は完了。実機の負荷履歴h更新と、学習時の駆動制限・モーター出力への接続が未完了 | 第28回Aと対応コードを固定し、生成した目標角度を関節順・符号・原点へ逆変換。実機の出力限界を反映 |
| 実荷重と終了動作 | 脚別試験は脱力で終了。全12軸・荷重時の停止は未検証 | 機体重量・リンク寸法・補強部品を学習モデルと照合し、支持補助下で保持と終了を確認 |

歩行モデルの周期を未検証の20Hzへ落として期限だけ合わせることはしません。一方、**固定姿勢専用の制御は、その周期と停止動作を別に検証したうえで先に進められます。** 通信改善と姿勢保持の開発を並行する理由です。

速度指令を0へ戻すことと、モーターの停止・脱力は区別します。初回歩行は終了までの処理を含めた有限試験とし、元の40cm/s目標を直ちに実機へ適用せず、検証した低速から始めます。

## 5. 手戻りを減らす運用

- 全脚の校正を毎回やり直さず、個体交換・向きの不確定・角度の不連続がある箇所だけ確認する。
- 接続と支持状態は試験開始時にまとめて確認。再起動、電池交換、手動調整など状態が変わったときに必要分だけ確認する。
- CANへ指令を出す実行担当は1つに固定。解析・コードレビュー・ログ集計は並行して進める。
- 1回の試験で指令、実角度、電流、通信遅延、停止結果をまとめて残し、「見えなかった」だけで同じ試験を反復しない。
- 追従未達ならその原因に作業を集中。自動反復や根拠のないゲイン増加、基準緩和で次段階へ進めない。
- 20msやモデル接続で止まった場合も、姿勢保持の成果と最初の具体的な障害を保存して終了する。

追加学習を最初には行いません。実機との接続で得た遅延・追従・機体差がモデルの成立条件を外れる場合に、その実測値を使ってシミュレーションの再評価・追加学習へ戻ります。
