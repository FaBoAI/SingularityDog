## 遅延について分かっていること

「前回の指令計算完了→今回の指令計算完了」が34.333334msを超えたことが、旧R3の停止理由。実際のCAN送信間隔とは別の測定値である。計算中は前回目標の保持指令を送っていた。

| 観測 | 数値・判断 |
|---|---|
| 旧10秒・初回 | 指令計算間隔38.481262ms。最初の要求は周期開始から5.177303ms、送信前確認は19.887710ms。残り112.290µsでは、過去の最短の確認→全軸書込み2.837028msにも届かない |
| 旧10秒・再測定 | 指令計算間隔34.868540ms。入力の間隔33.340489msに対し計算完了の位相が遅れた。native終了→Batch時刻は1.386382msで、復号・raw準備を含む |
| Jetson仮想通信の直接追跡 | 4系統のGIL再取得経路は最大1.079ms、1系統対照は最大10µs。1.079msには待機853µs、OS実行待ち140µs、その他86µsを含む |
| 新C++候補のMac比較 | 保持返信→電圧要求開始の中央値178.292→5.500µs。一方、native出力終了→Python収集は104.792→554.625µs。全体の高速化は未確定 |
| 重複検査の集約案 | 1周期で真正性検査16回、Session検査64回、FD確認128回。段階ごとへの集約の予想削減は約145µs/周期。未適用で、収集側増加全体を説明しない |

元の実機停止周期には直接CPU追跡がなく、当時のGIL／OS／main処理の内訳は復元できない。仮想実験には実CAN・USB、実IMU、モデル推論、現実のCurrentGuardがない。通信開始前の約4.3ms増加と、受信後の復帰遅延は別々に調べる。

両方の旧10秒試験は返信欠落なく、停止周期の新しい学習目標を送る前に停止した。全12軸STOP・設定復元・現物異常なしは確認済み。閾値を広げたり失敗周期を捨てたりして、完走記録へ変更しない。

## 次の担当者の実施順序

1. **版と資材を確定**：Gitのソース基準、私有モデル配布、既存凍結キットのmanifestを照合する。新配置先を使い、旧R3/R4を上書きしない。既定PLANでファイル・モデル・時計・SHAを先に検査する。
2. **ARM64・CPU検証**：Jetsonで新しい複合ライブラリをビルドする。ordinary・subset-stop・subset-active・native-groupの4ソースと生成物のSHA、ABI、CPU配置・timerのreadbackを確認する。同一複合DSOから作ったSessionだけを使う。別DSOのSessionポインターを渡さない。
3. **公平なCPU比較**：同じライブラリ・900µs／window3・モデルを含めるか否か・負荷・性能設定を揃える。従来／nativeを比較し、失敗周期も保存する。Macの500周期完走回は他検証と一部重複し、その後は旧56／新106周期で停止したため、速度優位の根拠には使わない。
4. **現実機を新記録へ結ぶ**：起動・40V電源区間・12軸個体・4ポート配線・角度・枝・電圧・姿勢を読み直す。過去の操作者回答を現在の条件として転用しない。ソース／ライブラリ／入力／model／IMU補正のSHAを固定する。
5. **無出力とゼロゲイン**：同じ新ソースで無出力5→501周期、条件を揃えた再測定、12軸200ms通信断保護、ゼロゲインType1を確認する。無出力STOP代理の成功と正のゲインでの実送信は分ける。
6. **箱支持2→10→20秒**：同じ設定で、実際の全軸host書込み、返信、追従、電圧・トルク、正常終了・全12軸STOP・設定復元、音声・現物観察を記録する。現在のソースでは2・10・20秒を扱う。60／120秒や大幅なゲイン・混合率への拡大は、この候補に含まれない。
7. **校正・モデル評価を完了**：未完の左移動・停止保持の評価、原点と静止速度、IMUの最終レビューを進める。加速度の大きさを直す候補と機体座標の絶対精度を区別する。
8. **荷重→自立→低速歩行**：箱支持の実出力成功後、別の荷重設定・支持・遮断・固定動画を準備する。人支持R4は最大8秒の現在位置保持、学習目標0、Kp6、支える力を緩めるのは最大0.5秒の別範囲である。100%学習目標による立ち上がりの実装・合格ではない。

各試験では、初回・定常・未完了周期を残し、処理時間、予定からの開始遅れ、入力鮮度、指令計算間隔、全軸host書込み、最終返信を別集計する。host書込みはCAN上のモーター受信時刻の証明ではない。終了STOPを確定できないときは40V遮断と支持維持へ戻し、その原票と新しい電源区間を残す。

## 校正で引き継ぐ具体的な残件

- **IMU**：[6方向の補正候補](imu-six-face-results-20261006.md)は左右を完全な反対姿勢と仮定せず、静止加速度の大きさから対角bias/scaleを求めた。別の通常姿勢2,909点への後方検算で平均ノルム10.656329→9.804436m/s²、平均ずれ+8.6643%→−0.02258%。この結果から取付回転・交差軸・温度・姿勢の絶対誤差は確定しない。rawと補正後を併記し、選択した補正を新contractへ結ぶ。
- **関節**：ID4・5・10等の手動方向候補と、全12軸の絶対原点承認は別。新しい姿勢へ参照を結び直すときも原点や符号を都合よく動かさない。[角度レビュー](angle-final-review-20261005.md)を参照する。
- **静止速度と水準器**：[解析・測定の限界と道具](stationary-velocity-origin-remediation-20261005.md)を参照する。USBカメラで動きが見えないことや気泡が中央へ戻ることだけでは、必要な分解能・絶対精度の証明にならない。未知の誤差はnullを維持する。

## 検証済みの範囲と再開用のCPU検査

ソース基準662ae9aの主要回帰491件は全件合格・省略ゼロ。別途モデル・時計等66件が合格。原因調査44件は42件合格、Mac上のLinux専用2件を省略した。実機のタイミング資格ではない。文書だけの今回更新で、実機成功や新たな回帰成功を追加していない。

以下はリポジトリ直下で行う代表的なCPU・ファイル・模擬通信の検査。491件全体の代わりではない。実CPUモデル検査には固定モデル配布とTorchが必要で、skipは合格に数えない。

```sh
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=runtime:runtime/tests:tools python3 -B -m unittest \
  experiments.four_bus_type1.test_type1_30hz \
  experiments.four_bus_type1.test_type1_initial_timing_evidence \
  experiments.four_bus_type1.test_native_group_runner \
  experiments.four_bus_type1.test_native_group_foreground \
  experiments.four_bus_native_group.test_native_group \
  experiments.four_bus_native_group.test_client \
  experiments.four_bus_human_hold.test_proposal_fixture \
  runtime.tests.test_policy_clock \
  runtime.tests.test_policy_model_30hz \
  runtime.tests.test_policy_observer_30hz \
  runtime.tests.test_policy_30hz_factories
```

multiprocessingを含む比較は、`python -m ...` または通常のファイルから起動する。標準入力の `<stdin>` をmainとして実行すると、spawn子がmainを再読込みできず、通信EOFを起こす。これは実CAN欠落の証拠ではない。性能比較は他のテストやコンパイルと重ねない。

公開確認は `python3 -B tools/check_publication.py --root . --files RELEASE_FILES.json`。新しいソース／文書は公開一覧へ追加する。凍結済み提案patchの空行コンテキストはSHAの一部であり、一般的な末尾空白整形で書き換えない。
