# 支持付き立位を先に確認する短縮手順 — 2026-09-27

追記：現時点の具体的な試験順・合格条件・時間は[立位試験前の最短テスト順](prestand-test-checklist-20260927.md)を参照。前脚付け根の「1秒保持→5°→10°」連続profileはコードと模擬試験が完成したが、**実機では未実施**。以下の単発10°の記録・見積もりを、連続profileの実機成功と混同しない。

目標を二つに分ける。まず既存の50 ms試験系を基盤に、**支持台上の固定立位**へ進む有限軌道を構築・検証する。現状の4軸診断ツールは全12軸の立位移行ランナーではない。学習済み方策の実機試験には別途、74観測の実入力、連続20 ms周期、駆動中の返信・全軸STOP・watchdog、現在位置から方策目標への滑らかな切替が必要である。固定立位を50 msで試せても、方策を50 Hzで実行できる証拠にはしない。

[9月25〜26日の結果](2026-09-25-26-hardware-status.md)では、全12軸の現在位置5秒保持とSTOPは通過した。前脚付け根ID3/6の10°軌道は最初の周期の返信鮮度判定で中断し、動作周期は0。最初の周期だけ125 ms、通常周期100 msとする修正はローカル試験済みだが実機未確認。前脚上脚を後ろへ動かす経路はカーボンポール固定具に接触し、付け根を水平側へ先に動かす迂回案も全経路は未検証である。

今回、初回125 msの判定ソースを無効化・有効化の凍結パッケージへ同梱し、作成後のハッシュと実際の125/100 ms判定を別プロセスで照合するようにした。同一起動の保持記録から前脚付け根10°の**無効化パッケージまで**一括準備するコマンドも追加した。さらに、前脚付け根10°の有効化試験に限って、6軸送信の5 ms間隔中に既着の返信を受け取る実験を組み込んだ。分割返信が次の送信時刻をまたいだ場合は次の指令を待たせ、期限内に返信の後半を受け取る。初回Enable完了直後の確認にも既存の125 ms判定を適用した。未送信ID・重複・誤宛先・欠損・期限切れは拒否し、全12軸STOPは維持する。無効化preflightで測った全12軸角と物理レビューを結び付け、実行時にどれか1軸でも確認済みの±3°を超えたらEnable前に停止する。ローカルではruntimeの1,220件を実行（1件skip）、関連ツールの20件が成功した。保存済みデータと一時的な模擬物理レビューで凍結wrapperの検査まで確認したが、Jetsonでの10°完走、実機での所要時間短縮、連続20 msの達成は未確認である。

最も早い姿勢確認は、40 VをOffにして機体を支えながら四足姿勢へ手で合わせ、12軸の生角度を一括保存し、その姿勢を保持できる場合に同一起動で現在位置保持を試す方法である。これは**手で作った支持付き姿勢の保持**であり、モーターによる起立移行や学習済み方策の成功ではない。4脚を同時に保持できない場合は無理に姿勢を作らず、下表の付け根先行経路を進める。

## 操作者が機体を保持する時間を減らす

|段階|機体を動かす前に準備すること|次の実機セッションで行うこと|目標時間*|
|---|---|---|---:|
|通信とパッケージ|新しい返信鮮度処理を実行パッケージへ凍結し、ハッシュと無駆動試験をローカルで照合|boot ID、前後ポート、12 UID・電圧・故障・STOPを一度記録|5〜10分|
|保持|前回の合格基準とログ収集を一つの手順へまとめる|現起動で現在位置5秒保持を一度だけ確認|5〜10分|
|前脚付け根|現在角からのID3/6最大10°経路を用意。旧bootの絶対角を流用しない|支持台上、全経路の隙間を現物で確認してから有限移動と全12軸STOPを記録|10〜20分|
|立位への通路|付け根先行→上脚の順でCAD・現物を照合。干渉があれば機械配置を先に直す|通れる組だけ4軸単位で動かし、追従しない軸だけ個別診断|15〜30分|
|固定立位|現角からの有限軌道と停止点を事前に計算|支持台を残して静的な四足姿勢を短時間保持し、12軸・IMU・STOPを記録|20〜30分|

\*時間は必要なソフトと安全な経路の準備が終わり、通信・動作が一度で通る場合の**試験枠の目標**で、実測値や到達保証ではない。全12軸の立位移行ランナー、パッケージ作成・コード修正・干渉部品の再印刷に要する時間は含めない。次回は最初の10°試験までを優先し、停止したら全脚の校正や保持を最初から繰り返さず、その起動のログで失敗区間だけ直す。

## 立たせるまでの再見積もり

|到達点|必要な作業時間の目安|前提・判定|
|---|---:|---|
|前脚付け根10°の実機再試験|30〜60分|Jetson接続・40 V・支持台・干渉しない現経路が整い、同一起動の保持記録を取得できる場合。凍結ソースの修正と一括準備で反復作業を減らす。|
|支持台を残した固定四足立位の初回試験|合計5〜11時間、最短1〜2作業日|上記再試験に加え、前脚の干渉回避経路確認1〜2時間、全12軸の有限立位移行ランナー実装・模擬検証3〜6時間、支持下の段階移動・短時間保持45〜90分を見込む。各区間を同一起動で保持し、脱力による位置戻りを避ける。|
|支持台を外した四足起立|固定立位の後に追加2〜4時間を暫定確保。合計7〜15時間、最短2〜3作業日|荷重を少しずつ四足へ移し、12軸の保持・電流・IMU・脚と固定具の隙間を確認する。負荷で姿勢が崩れる場合はその場で中断し、所要時間を再見積もりする。|
|学習済み方策による起立・歩行|固定立位とは別の開発枠|実目標送信を含む連続20 ms、74観測と角度対応、支持下の方策切替が未検証。単発約20 msのSTOP代理送信を合格扱いしない。|

上の5〜11時間は接触を避ける経路が存在し、通信試験が一度で通る場合の作業見積もりである。カーボン固定具との干渉が解消せず、CAD変更・再印刷が必要なら、その日数を追加する。開始時に支持・離隔・即時40 V Offをまとめて確認し、その後は各区間の停止結果と現物の接触だけを次へ進む判定にする。異常や通信断があれば全12軸STOPを確認し、その区間のみ直す。

現起動の保持記録ができた後は、[ローカル準備ツール](../tools/prepare_front_hip_step10_disabled.py)で前脚付け根10°候補と**無効化専用**パッケージを一回で作る。凍結した`rs05_joint_trial.py`の初回125 ms／通常100 msの判定も作成時に検査する。有効化パッケージの作成、Jetsonへの転送、実機駆動はこのコマンドには含まれない。

```sh
python3 -B tools/prepare_front_hip_step10_disabled.py \
  --source-disabled /path/to/current-boot-disabled-source \
  --current-hold-summary /path/to/current-boot-hold-summary.json \
  --output-root /path/to/new-output-directory \
  --tag front-hip-step10-r1
```

この無効化パッケージのpreflightが同一起動で通過した後、次のコマンドで実測12軸角とpreflightのSHAを物理レビュードラフトへ自動転記する。**ドラフトの物理確認欄はすべてfalseのまま**なので、有効化には使えない。

```sh
python3 -B tools/prepare_front_hip_clearance_review.py \
  --disabled-package /path/to/front-hip-step10-r1-disabled \
  --preflight-log /path/to/passing-preflight-log \
  --output /path/to/new-physical-review-draft.json
```

操作者はドラフトの12軸姿勢を基準に、**各軸±3°の始点変動を見込んでも、ID3＋10°／ID6−10°の全経路で黄色い部材・カーボン固定具・配線に隙間があること**を現物で確認する。12軸の全組合せを動かす手順ではない。隙間を確認できなければ有効化せず、姿勢を変えて無効化preflightからやり直す。確認内容を`start_tolerance_clearance_note`へ書き、既存の物理確認欄を確認した項目だけtrueにする。実行時も現在の経路を再確認する。有効化ランナーは始動直前の12軸実測角をドラフトの基準角と比較し、1軸でも3°を超えればEnable前に停止する。以前の物理レビューにはこの±3°確認がなく、そのまま再利用できない。

前脚の接触は停止閾値を緩めても解消しない。停止条件は「UID・故障・欠測・古い返信・予期しない大変位・STOP不成立」と「短い追従差・静止速度ノイズ」を分け、後者は診断記録を最後まで取れるよう場面別に扱う。全12軸STOPと異常時の40 V遮断可能性は維持する。

単発の5°試験を毎回STOP・脱力で終えると、脚が重力で元の位置へ戻り、次の5°が累積しない。準備すべき立位移行ランナーは、**現在位置保持→検証済みの小区間移動→終点保持→現物とログの確認→次区間**を同一セッションでつなぎ、異常または終了時には全12軸STOPする。区間ごとの新しい始点は実測値とし、古い起動の角度や前段の指令値を再利用しない。これは設計方針であり、現行の4軸診断ツールには未実装である。

## 方策の実機試験は並行して準備する

固定立位の機械試験中に、Jetson側では無出力の連続計測を独立して進める。現在の実入力→推論→STOP代理送信は**単発3回の中央値20.063 ms、最大20.136 ms**で、返信までの中央値は22.791 ms。周期の開始予定時刻から最後のホスト送信までは3回とも20 msを超えた。こちらは送信間隔0.6 ms、未返信上限3件の高速診断である。一方、現行の**駆動試験ランナーだけ**は5 ms間隔を維持するため、6軸分のwriteは少なくとも25 msかかる。今回の中間受信は待機時間を重ねるが、この送信下限を変えない。高速診断の仕組みを駆動指令へ移すには、実機で欠測・STOPの挙動を確かめ、1,500周期で入力年齢、p99、最大、期限超過、実目標送信を確認する。

学習済み方策は固定立位が安定し、74観測の符号・単位・負荷履歴と最初の目標差を確認した後に、現在角から段階的に寄与を増やす。支持台上の固定立位、方策立位、荷重移行、歩行をそれぞれ別の結果として記録する。
