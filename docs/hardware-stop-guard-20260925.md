# 起動確認処理の軽量化と実機比較 — 2026-09-25

**前6台の個別STOP通信で、最初のホスト書込み開始から全返信まで38.281ms→30.223msを観測しました。各条件1回の暫定比較で、全工程20msは未達・未検証です。** FW更新は行っていません。

## 変更と検証

`active_report_probe.py`と`stop_batch_experiment.py`に、既存の`BootIdentityGuard`を適用しました。起動IDを読むたびにファイルを開閉する処理を、試験中に所有するFDからのfresh `pread`へ置換しています。確認頻度・通信フレーム・期限・ポート確認は維持しました。全ワーカー終了後にFDを閉じ、閉鎖失敗も未完了として扱います。

ローカルのruntimeテスト856件、Jetsonの凍結r7パッケージのテスト135件が通りました。初期失敗、ワーカー起動失敗、停止処理中の検査、FD閉鎖順序も確認しています。既存のr6パッケージは変更せず、r7を別に保存し、転送後に全52ファイルのハッシュを照合しました。

## 同条件のA/B結果

前脚側ID1〜6、UART 921600bps。1台につき17バイトの全ゼロType4 STOPを送り、返信を待ってから次のIDへ進みます。6台分の一括書込みは行っていません。

| 測定区間 | r6・修正前 A | r7・修正後 B |
|---|---:|---:|
| 最初のホスト書込み開始→最後のホスト書込み終了 | 34.825ms | 27.155ms |
| 最初のホスト書込み開始→最後の返信 | 38.281ms | 30.223ms |
| 返信数 | 6/6 | 6/6 |
| mode0／fault0、終了時100ms静穏、ポート閉鎖・排他解放 | 確認済み | 確認済み |

この1組では返信完了まで8.058ms（約21%）短縮しました。ただしA→Bの各1回で、再現性・最大遅延の保証ではありません。事前確認と終了時の静穏待ちは上記区間に含めていません。

1台ごとの往復時間の中央値は3.484ms→3.250ms、最大は3.531ms→3.702msでした。6台分の合計短縮を、個々の最大往復時間やUSB／CAN物理遅延の改善とは解釈しません。

この試験は、既存の未応答上限4・送信間隔0.5msの方式と異なります。以前の取得・推論・送信を含む37.780msから今回の8.058msを直接差し引くことはできません。IMU・AI推論・学習済み目標送信も今回の測定には含みません。
