# 実機開発のまとめ — 2026-09-24

**4脚それぞれの小角度動作と停止を確認し、実センサー入力から推論・送信までの時間を計測しました。全工程は約38msで20ms未達です。学習済みモデルでの実機起立・歩行はまだ開始していません。**

## 最新の全工程計測

前後CAN・IMUの3担当を同時に開始し、入力が揃った後に1つの方策を推論、前後バスへ並列送信しました。全工程を同じホストの時計で直接測定しています。

| 測定区間 | 中央値 | 最大 |
|---|---:|---:|
| 並列取得 | 14.483ms | 14.659ms |
| 入力組立・再検査 | 3.671ms | 3.803ms |
| 入力検査・推論・結果変換 | 9.642ms | 9.693ms |
| 最初〜最後のホスト送信 | 9.467ms | 10.054ms |
| **最古入力の取得開始→最終ホスト送信** | **37.780ms** | **39.089ms** |
| **最古入力の取得開始→最後の返信** | **40.416ms** | **41.572ms** |

3回の独立した単発試験で、20ms未満は0/3回。全体時間には受渡し・同期も含み、表の中央値の合算ではありません。USBへの書込み完了とCAN線上の送信完了も区別します。

**送信は全ゼロ停止命令による代理測定です。推論目標をモーターには送っていません。** 各回36要求／36応答、停止返信mode0/fault0、全担当終了、通信ポート・排他解放、IMU設定復元を確認しました。事前warmupと個体識別は計測区間外で、h=0の診断仮説を使っています。連続50Hzや最悪時間の保証ではありません。

## 次に進める順序

1. **重複処理と通信往復を減らす。** 入力組立の再デコード・コピー・証跡生成を整理し、ID・鮮度・故障・範囲の判定は維持する。通常の状態返信を次周期へ渡す方式は、元の入力時刻を保って検証する。
2. **同じ条件で再計測する。** 単独時と統合時の推論時間差を切り分け、取得→推論→実際の指令送信を通した遅延、入力年齢、欠測、期限超過時の停止を確認する。
3. **実機投入の条件を揃える。** 校正・Type2換算・IMU・出力範囲・全軸停止を確定し、支持補助付き保持、短い立位、低速前進と停止へ段階的に進む。現在の結果だけでは歩行開始条件を満たしていない。
