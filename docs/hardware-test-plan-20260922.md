# 2026-09-22 実機テスト計画

この20分枠は[Deploy全体計画](deployment-roadmap-20260922.md)の「B：脚別試験」に相当する。
校正整理・IMU・通信・ライブ無出力・全軸停止の事前準備と、後段の支持付き立位・学習済み方策駆動は別の到達点として管理する。

最初の20分は、残り3脚の小角度動作・停止確認を終え、12関節の動作確認表を揃えることを目標にする。
今日確認できた右前脚の試験は繰り返さない。電源再投入後の個体・現在角度・停止状態の確認は毎回行う。
20分で学習済みモデルによる起立まで完了する約束ではない。

## 今日の到達点

- 右前脚ID1・2・3の同時小角度駆動を実施。5秒試験と、5°指令を2段階に分けた試験が完了し、毎回3関節の停止応答を確認した。
- 操作者から最終的に「問題なく動いた」と確認。途中の異常選択と、その後2回の明示的な訂正は原記録へ保持した。
- 5°指令に対する各段階の実測は約2.80〜4.63°。2段階試験の最初から最後の駆動中位置までの差は約6.15〜6.52°で、10°到達とは扱わない。
- 停止は脱力であり、保持ではない。段階間や最後の停止後にも位置が変化した。特にID3は最後の駆動位置から事後測定まで約7.10°変化しており、保持精度と混同しない。
- 新しい静止判定は支持台上の右前脚の相対試験限定。ローカル・Jetsonとも関連47テスト通過、3回の駆動ログを生フレームから検証済み。

## 時間を使わないための開始前準備

1. Jetson用・40V用のバッテリーを十分充電する。外付けUSBカメラは全脚と支持台が見える位置に接続しておく。
2. 左前・右後・左後の保存済み校正／個体情報を先に検証し、動作方向・位置応答の根拠を脚別に整理する。右前脚専用の証跡を他脚へ流用しない。
3. 他脚の限定試験設定を実装・オフライン検証し、Jetsonへ配置しておく。現状のposition-v2はFR専用なので、脚名を書き換えるだけでは開始しない。
4. 接続、共通検査、脚別試験、停止確認、結果保存を一つの対話ランナーへまとめる。これは追加実装が必要な準備項目で、現時点で新しい統合コマンドが完成したとの意味ではない。
5. 10°試験は、2回の脱力を挟まず1本の連続した緩やかな軌道として準備・検証する。可動範囲・離隔・時間・速度・停止条件を先に定義し、現場で利得や判定閾値を変更しない。
6. CAN側1Mbpsを確認する。UART 921600bpsとは別設定であり、既にCAN 1Mbpsなら変更しない。現アダプタに対応する設定確認方法を確定したうえで、無駆動の12軸通信計測を行う。設定変更だけで20ms周期に収まるとは扱わない。[通信改善方針](can-readonly-timing-probe.md#can-1mbpsの確認と20ms周期への改善方針)を参照。

## 最初の20分

| 経過 | 実施内容 | 操作者の操作／終了条件 |
|---|---|---|
| 0〜3分 | 接続を1本に固定。全12個体、電圧、現在角度、通信、IMUの取得、実行中プロセスを一括確認 | 冒頭に支持台・全脚離隔・手離し・即時電源Offを1回確認。不成立は駆動せず停止 |
| 3〜6分 | 左前脚ID4・5・6を3関節同時に小角度駆動し、停止まで自動実行 | 1脚が終わったら「OK／異常」を1回だけ入力 |
| 6〜9分 | 右後脚ID7・8・9で同じ確認 | 前脚の停止確認と現物OKを条件に次へ進む |
| 9〜12分 | 左後脚ID10・11・12で同じ確認。交換済みID11の個体・角度飛びも確認 | 不調があればその脚で打ち切り、ログ保存 |
| 12〜17分 | 準備・検証済みの場合のみ、右前脚の連続10°軌道を1回実行し、見た動きと実測角度を比較 | 到達角度・最大速度・停止後の変化を分けて記録。単なる「動いた」で追従成功にしない |
| 17〜20分 | 12関節の確認表と課題を自動集計し、停止状態を確認して終了 | 外出前に40V電源Off。以降はログ解析のみ |

開始前のコード検証・配置が未完了なら、まずそこを完了させ、上の20分枠の開始時刻を明示する。
通信障害や異常時は、その場で同じ試験を繰り返さず原因とログを確保する。
一度に動かすのは1脚のみ。次脚への駆動は、直前の停止確認と操作者の現物確認の後に行う。

## 次の段階へ進む条件

- **支持付き四足姿勢**：12関節の部位・方向・原点候補・可動域をモデルと照合し、現在姿勢から小さい連続変位で目標へ接続できること。付け根ID3/9/12がモデル可動域外となる問題と、電源再投入をまたぐ角度の扱いを解消する。
- **姿勢保持**：移動中、保持中、停止後の脱力を分離して確認する。目標未到達を大きなKpやトルクの追加だけで解決しない。
- **学習済みモデル**：まずモーターへ出力しない推論で観測と目標角を検証する。現在の12軸逐次読み取りは約81msで、方策の20ms周期に間に合っていない。通信周期・モデル原点・IMUの約9%偏差と軸方向、12軸ランナーの停止処理を解決した後、支持下の短時間試験へ進む。

初日の達成指標は「残り3脚の動作と停止が確認できたか」「10°軌道の追従量を測れたか」。
床上歩行や全脚同時の学習済みモデル駆動を、時間だけを理由に開始しない。
