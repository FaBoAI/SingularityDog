# 充電後の20分実機テスト計画

この文書は9月21日の開始前計画を残したものです。終了時の結果は[当日集計](hardware-results-20260921.md)、次回の段取りは[9月22日の計画](hardware-test-plan-20260922.md)を参照してください。

作成：2026-09-21。これは実行計画であり、学習済み方策の実機駆動を完了した記録ではない。

目標は、選定モデルをJetsonへ配置して実センサー入力による推論を確認し、駆動条件が揃った場合に支持台上で短時間の方策駆動まで進めること。
20分の現場枠は、充電・再接続と下記のソフトウェア準備が済んでから開始する。事前実装の時間は別途必要で、現状から20分以内の実機駆動を保証するものではない。

## 現在地

- 4脚・20姿勢の手動記録と、12軸の原点・正方向の候補は保存済み。全姿勢を最初から取り直さない。
- ID11は交換後の個体で記録済み。短い静止記録では以前の大きな値飛びは再現していない。
- 最新のID1の5°試験は、実測約4.71°、停止応答あり。操作者も動作と異常なしを確認した。
- 脚1本の3関節を同時に動かす固定軌道ツールは実装済み。全ローカル239テスト合格。Jetson配置と実機試験は接続切断により未実施。
- 現在の診断ツールと学習済み方策を結ぶ12軸実行処理は未実装。IMU補正・モデル座標・実測可動域・通信断停止の検証も残る。
- 最後の確認ではSSHと外付けカメラが利用できなかった。充電後の電源再投入で原点が維持されるかも改めて確認する。

詳細：[現在の実機確認記録](hardware-readiness-20260921.md)。

## 現場枠の前に準備するもの

1. **モデルと対応コードを固定する。** 初回候補は第28回Aの歩行方策 `model_149.pt`。重み、学習時の設定、SwingCore、観測変換を一組にし、チェックサムと入出力を照合する。74入力・12残差出力をCAN角度として直接送信しない。
2. **無出力推論を接続する。** CAN角度・速度、IMU座標変換・姿勢推定、観測の時刻、74列の意味を対応させる。その他の観測値も学習時と同じ定義で計算し、欠けた値を黙って0で埋めない。未検証の校正候補を使う診断結果には、その旨を付ける。
3. **50Hzの実行経路を測定する。** 診断の低速読取りや20Hzの脚試験を、そのまま50Hz方策へ転用しない。CANの受信・推論・指令・ログの最悪時間とデータの古さを記録し、遅延・欠測時は出力を止める。モデルの時間刻みを無断で変更しない。
4. **駆動経路と停止処理を統合する。** 全12軸の識別、モデル順、原点・符号、実測制限、初期姿勢への移行、全軸停止を実装・オフライン検証する。学習済み歩行モデルに、自然垂下からの起立を任せない。
5. **一続きの操作画面を用意する。** 自動診断→脚別試験→推論→条件判定→終了報告を一つのCLIにまとめる。これは今後作る機能で、現時点で統合コマンドは存在しない。センサーだけの無出力処理にはモーター有効化機能を持たせない。

充電中に進められるのはローカル実装・過去ログ再生・試験用ファイルの準備。実機でしか確かめられない未検証項目を、事前準備済みとして扱わない。

## 20分の進め方

| 経過 | 作業 | 次へ進む条件 |
|---|---|---|
| 0–2分 | 全12軸のID・交換後個体・角度・電圧・通信、IMU、外付けカメラを一括取得。支持と足の離隔を現在の状態で確認 | 応答と個体対応が揃う。電源再投入後の角度を既存校正と照合できる |
| 2–8分 | 右前→左前→右後→左後。脚1本の3関節を同時に各5°以内で1回動かし、各脚の前後値・停止・映像をまとめて確認 | 脚ごとに予測方向、周囲との離隔、追従と全3軸停止が一致。曖昧な関節だけ追加確認 |
| 8–11分 | IMUの静止値・重力方向・取付軸を短い計測で照合。関節角度のモデル変換も一覧で点検 | 既存の補正・姿勢推定の妥当性を確認。約9%の偏差や範囲外の付け根角度を未解決のまま合格にしない |
| 11–15分 | モデルをJetsonで起動し、実センサーを入力して30–60秒推論。モーターへの出力は無効 | 観測列、状態の更新、50Hz周期、出力の有限性・連続性、目標角度と現在姿勢の差を記録 |
| 15–18分 | 下記の駆動条件がすべて成立していれば、支持台上の対応した初期姿勢から数秒の制限付き方策駆動を1回。未成立なら該当箇所の診断を続ける | 現場の動きとテレメトリーが一致し、試験終了時に全軸の停止を確認 |
| 18–20分 | 全12軸の事後読取り、動画、モデル版、成功・未達・次の1件を保存 | 無出力推論、固定軌道試験、方策駆動を区別した結果が残る |

時間配分は目標。ある段階が不成立でも残り時間を理由に次の駆動段階へ進まない。
例えば、11分までにIMUの未解決事項が残る場合は、残り枠で未検証入力としての無出力診断と原因の記録まで進める。

## 方策による駆動へ進む条件

- 全12軸の個体・部位・モデル上の原点と正方向・試験範囲が根拠付きで確定している。電源投入をまたぐ校正の有効性も確認している。
- IMUの取付変換・補正・姿勢推定が検証され、実センサーと方策の時刻が整合している。
- 通信断時の停止が対象の全モーターで実測確認され、今回の全軸停止経路と再有効化しない動作が検証されている。timeout値の読戻しだけで代替しない。
- 12軸の実行周期と全関節の応答を確認し、選定した方策・初期姿勢・ゲイン・制限を一組として検証している。
- 支持台、脚・配線の離隔、操作者の即時電源遮断が現在の状態で成立している。

これらは現在すべて成立しているわけではない。20分枠の中で確認できなければ、その枠の成果はモデル配置・無出力推論・脚別試験までとなる。
支持台上では接地が学習時と異なるため、短時間の方策駆動が成功しても床上の起立・歩行成功とは扱わない。

## 確認を速くする方法

- 端末操作を一本化し、操作者は各脚の「正常／異常／判別不能」を一度ずつ返す。正常でも次の脚を無人で自動開始しない。
- 既存の20姿勢・モデル・ログを再利用し、値が変わった個体や曖昧な関節だけ再確認する。
- 全12軸の読み取りを一括評価し、脚の試験中に別プロセスからCANを開かない。
- 3関節を同時に動かした映像だけで各関節の正方向を確定しない。個別テレメトリーとモデル予測を合わせて判定する。
- エラーを自動再試行やゲイン増加で隠さない。未解決項目があれば次の駆動を止め、残り時間を原因特定と記録へ回す。
- 写真・動画・個体識別情報・生ログは非公開領域へ保存する。

完了時に、`モデル配置`、`実センサーによる無出力推論`、`脚別固定軌道`、`学習済み方策による駆動`の4項目をそれぞれ実施／未実施で報告する。
