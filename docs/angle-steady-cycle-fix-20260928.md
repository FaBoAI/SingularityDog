# 9月28日夜：電源再投入の角度補正と初回・定常周期の分離

40VのOff→On前後を同一起動で読み取り、12軸のUID一致と角度差最大0.008524°を確認した。操作者は「40V Off→On完了・姿勢は同じ」と確認している。**今回の操作では360°ずれは再発しなかった**ため、ずれが発生した実機での補正成功とは区別する。生記録と前後比較はMacへ保存した。

その後の[5回連続の再投入比較](power-cycle-repeat-20260928.md)でも360°ずれは出なかった。全12軸の`zero_sta=0`を読み取り、起動時の0〜2π範囲への再初期化が過去の一回転差と整合すると確認した。ただし3回目には最大3.306°の非周回変化が残り、原因の確定と原点・正方向の現物照合は完了していない。

## 角度補正の修正

読み取りと実出力の逆変換に、同じ通電区間の固定補正を使う。

```
q_model = sign × raw + offset_current
offset_current = offset_calibration − sign × turns × 2π
raw_target = (q_target − offset_current) / sign
```

`turns`は、確認済みの機械可動域と角度誤差を含めて一意に選べる場合だけ決定する。従来の有限候補列挙を共通の数式へ置き換え、実出力前の判定にも機械可動域・誤差幅を使うよう修正した。読み値を単純に`%360`へ置き換えると、現在のQDD座標と送信目標の座標が食い違うため、この固定補正を両方向へ適用する。

通電区間が不明、候補が複数、誤差幅が機械限界を超える場合は有効化前に中断する。同じ通電区間で読値が急変しても自動で再補正しない。通電区間ラベルだけで電源操作を自動検出できるわけではなく、原点・正方向・機械範囲の現物確認も別に必要である。

過去のID3の+361.307°とID9の負の一回転を再現するテストで、補正後の現在角とType1送信値の逆変換が一致した。関連240テストと出力スモーク9テストを確認し、Jetsonでも角度・実出力ランタイム・待機処理の69テストを確認した。件数には重複があり合算しない。実機へType1指令を送った検証ではない。

## 初回1周期の扱い

操作者の「開始の1回は20msを超過してもいい」に合わせ、初回1周期と定常500周期を分けて判定する選択肢を追加した。全501周期の取得・推論・26要求の返信・後処理と生時刻は保存し、初回の超過も集計から消さない。途中の超過は引き続き失敗として数える。

次の三つを別々に報告する。

- 実開始から返信後処理終了までの処理時間が20ms以内か。
- 固定20msスケジュールの終了期限に間に合い、周期を飛ばしていないか。
- 定常周期の実開始間隔が厳密に20ms以内か。微小なスケジューラ遅延も記録する。

名目20msで起動する処理では、実開始間隔に起動遅延の差が乗る。中央値が20ms、あるいは処理時間だけが20ms未満でも、厳密な開始間隔の合格とはしない。許容ジッターやモデルの20ms刻みは変更していない。

選択式のC++期限待機も追加した。取消FDを監視しながら期限直前まで待機し、最後の200/500µsだけ時計を確認する。シリアル機器を開かず、待機後の実時刻を記録する。既存ライブラリは、この機能を選ばない場合に引き続き使用できる。既定設定には採用していない。
