# 9月30日：総合課題表と修正結果

次の実機作業は、新しいキットをJetsonで照合し、箱を残した5秒の微小伸展・復帰を検証すること。ソフトの異常処理、入力、配布・証拠保存を追加監査して修正した。この監査ではJetsonへの通信・駆動は行っていない。

○は記載範囲の確認済み、△は一部確認または実機再検証待ち、×は未達。過去の実機成功、現在のソフト試験、次の実機開始条件を分けて管理する。

## 今回の修正

| 再現した問題 | 修正と回帰検証 |
|---|---|
| 取消コールバックが例外になるとSTOP結果のレポートまで失う | エラーを保持し、前後CANの停止を独立して手配。両STOPが確認できても手配エラーを正常終了にしない。再入を一度だけ処理 |
| 独立した標準出力の詰まりで箱交換の合図が停止する | 入力と出力の両FDを非ブロッキング化して復元。実PTYを満杯にした回帰試験で確認 |
| 期限後のEnterが、期限確認より先に受理される | 受理時刻で既存の8秒期限を検査。遅い応答は記録し、保持終了へ進む |
| 生IMUと称した入力の補正済みフラグが消え、補正を再適用する | live・replay・observerで8種の補正状態を共通検査。補正済み・不明値は推論前に拒否 |
| 有限のdouble値がfloat32モデル入力でInfになる | forwardと再利用バッファ更新の前に表現範囲を検査。実torchで巨大な有限値の拒否を確認し、最大有限値も境界試験で確認 |
| 原点の推定中、有限値からInf／NaNの候補が生まれる | 角度幅・区間・中心・不確かさの導出値も有限性を検査 |
| キット準備やレビュー待ちの間の変更を見逃す | 一時領域で組み立て、元とコピー先を再ハッシュしてから発行。生ログ・動画もレビュー結合時に再確認 |
| 子プロセス起動後の記録失敗・中止で、処理が残ったままロックが解放される | 起動した子の停止処理をロック内のfinallyへ移動。SIGINT／SIGTERM、記録失敗、タイムアウトを検証。子プロセス終了をQDDのSTOP確認とは扱わない |
| JSONの欠落値・型の違い・重複キーで終了成功と誤判定する | 同じ読取りバイト列を解析・ハッシュし、キーの存在と値の型も比較。重複キーとNaN／Infinity定数を拒否 |
| 新キットの説明が旧試験のまま | V3へ未承認の5秒経路テンプレートと9月30日文書を追加。V2の既定は維持。支持撤去・歩行・自動再試行は許可しない |

送信間隔0.9ms・window3、トルク・可動域・速度監視の上限、校正値、学習済み重みは変更していない。角度・IMU入力の追加検査が制御周期へ与える実時間の影響も、Jetsonで測り直す。

## 再開の順番と所要時間

1. 新キットの配置・ビルド・ハッシュ照合：30〜60分。
2. 現電源の無出力診断、箱を残す5秒往復、荷重用モデル設定の支持付き確認。
3. 受けを維持した部分荷重、四足自立、低速・短距離歩行、ログと動画の回収。

2〜3の内訳は[歩行計画H1〜H7](walking-plan-20260930.md)。全段階が初回で通る場合、配置を含め150〜290分（約2.5〜5時間）の作業枠。通信・追従・接地・必要トルク・機構の問題が再発する場合は再見積りする。歩行成功時刻の保証ではない。

同じ起動・電源・姿勢・ソースの準備はまとめ、変更のあった条件だけ更新する。過去の20ms成功やSTOP成功を新キットへ自動で引き継がず、機体を動かさずに確認できる範囲は先に済ませる。

## 検証と保存

| 検証範囲 | 結果 |
|---|---|
| 全ランタイム | 2,341件中2,337件成功、失敗0、4件skip（非公開の保存入力・通信原本を未指定） |
| 全ツール | 424件中423件成功、失敗0、1件skip（Linux向けの孤立プロセス停止試験をmacOSで省略） |
| リポジトリ共通・ジョブ実行 | 32件すべて成功。完了記録・timeout・detach・共有ロックも確認 |
| 5秒往復の専用検証 | 54件すべて成功。上記ランタイムの部分集合で、合計へ重複加算しない |
| r64履歴ソース | 全178件一致、9件を別保存 |

重複を除く全体は**2,792件成功・5件skip・失敗0**。スキップした保存モデル比較を、新しいモデル同等性の実証には数えない。実PTYの出力詰まり、実子・孫プロセスの終了、C++エンコーダーとのbyte一致も確認した。

全件実行では、通常動作とtimer-slack所有者のテストがホストの短い期限に依存して不安定だった。通常動作は共通の模擬時計へ、timer-slackの所有者・復元は実C++の準備完了地点での意図的な終了へ変更した。実時間のwatchdogテストと実C++の連続周期テストを残し、その後の全件実行で上記結果を確認した。実機の周期や監視上限は変更していない。

現在のソースに対応した[5秒往復の専用検証結果](../evidence/supported-preload-software-20260930-r3.json)と[実行ログ](../evidence/supported-preload-software-20260930-r3.json.log)を保存した。r1／r2の結果は各旧ソースの履歴として残す。擬似通信とホスト上の試験は、Jetsonの20ms実測・現物の接地や荷重・実行許可の代わりにはならない。

[r64の試験済みソース](../runtime/tested_sources/20260929-r64/README.md)は178件のSHAを維持し、開発版と異なる9件を別保存した。旧結果を現在のソースの結果へ書き換えていない。

学習モデル自体の規模とESP32移植の切り分けは[モデル規模](model-footprint-esp32-20260930.md)を参照。ESP32移植は現在のJetson実機再開には必須ではない。
