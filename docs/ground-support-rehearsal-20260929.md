# 胴体支持台の入れ替え記録（2026-09-29）

機体は段ボール箱で胴体を支え、4足を床へ接地させている。操作者は1人。低い箱を別の荷重点へ先に差し込み、胴体下の受けを残したまま高い箱を外して元へ戻せる、と申告した。40VをOffにした無駆動の入れ替え・復帰を1回行い、操作者は完了を報告した。Jetsonログと同期した動画、受け面の最大隙間、箱の耐荷重、滑り・変形の測定値はまだない。

この記録は**箱の入れ替え手順の予備確認**である。独立した固定式落下受けの審査、部分荷重、自立、歩行の合格には使わない。次の実機段階では、40V Offで全重量を受けた状態の箱の安定性と、入れ替え中も胴体直下の受けが数mm以内に残ることを横動画で確認し、その元動画を試験ログと結び付ける。受けの変形・横滑り・脚や配線への接触があれば支持付き状態へ戻す。

先行する起動で箱を残した学習目標0.5%・最大1°・Kp3/Kd0.15の2秒試験は完走し、全12軸STOPを確認した。出力角の実移動はごく小さく、胴体荷重を脚が受けた証拠ではない。支持台を下げる実験には、別途、校正・IMU・通信停止・出力範囲・実周期を結び付けた地上試験用の新しい審査済み設定が必要である。

参照：[地上試験の段階判定](ground-trials-20260928.md)、[実出力と20ms計測](20ms-fast-voltage-benchmark-20260929.md)。

## 新設定の実出力完走後に残ること

STOP再送版で箱支持の学習目標送信を97周期完走し、全工程最大19.575ms・全12軸STOP・操作者の現物異常なしを確認した。[結果](../evidence/supported-policy-stopretry-20260929.json)。これは最大1°・Kp3/Kd0.15・モデル混合率0.5%の限定試験で、実角変化は最大約0.066°だった。

荷重を受ける試験は次の順に準備する。過去の箱の入れ替えリハーサルは再利用し、未確認の寸法・受け止め条件を埋める。

1. 高低2つの箱の高さ差をmmで確認し、低い受けが交換中も胴体直下に残るか確認する。潰れ・滑りに対する全重量の保持は未確定値を自動補完しない。
2. 箱を残した現在姿勢保持で、立位用ゲインとトルク上限を検討する。現在の0.5%モデル出力と約0.040Nmの最大読値から、荷重を支えられる設定とは判断しない。ピークトルクを連続保持値として採用しない。
3. 胴体と受けの隙間・4足が見える映像をログに合わせ、最初は短い部分荷重と全支持への復帰を記録する。脚からのトルクだけで荷重率を推定しない。
4. 部分荷重で滑り・沈み・過負荷がないことを確認後、独立した受けを残して短時間自立へ進む。学習モデル単独の自立は、モデル混合率0.5%の試験とは別に評価する。

この段階では新しい荷重試験の実行許可や設定承認を作成していない。全12軸はSTOP済みで、箱を残している。

## 10cmから12cmへ台を変更した後の準備

操作者は高い箱12cm、低い箱10cmと回答し、硬い板を固定して受けの隙間を2〜3mmに調整したと報告した。その後、胴体を10cmの箱へ載せ、さらに12cmの台へ戻した。最後の申告を現在位置として扱い、10cmの角度記録を実出力用に流用しない。板が現在どこにあるかと実際の落差は、台の高さだけから推測しない。

新起動で12軸のゼロゲイン通信断保護と全軸STOPを確認した。12cmへ移した後の読取りは静止しており、10cm記録との差は最大約28.05°だった。次の実出力候補は**箱を残した現在位置保持3秒、Kp12/Kd0.15、ゲイン立上げ1秒、モデル混合率0**である。保持用ゲインを上げる数値契約を追加し、モデル混合率がゼロ以外なら従来のKp3・推定PDトルク0.1Nm上限を維持した。保持時も推定PD0.5Nm、読取りトルク1Nm、追従差2°などの監視は残す。

プロフィール・実出力ランナー・滑らかな開始停止の146テストが通過した。合成バス試験ではモデルが毎周期異なる目標を返しても、混合率0なら12軸の送信位置が初期値から変わらないことを確認した。これは実物の保持・荷重能力の合格ではない。3秒保持の実機実行は、12cm姿勢の確認と現起動の計測を結び付けてから行う。

参考のファイル上の幾何計算では、12cm姿勢から胴体を2mm上げる固定付け根経路に必要な最大関節変化は約3.96°だった。URDF・原点・床接地を仮定した計算で、荷重・全経路干渉・実際の上昇量は未検証。最大1°の学習目標試験の結果で、この経路を実行可能とは判断しない。

## 12cm箱での学習モデル実出力 r1 / r2

操作者の希望により、現在位置だけを保つ3秒案から、実際の学習目標を混ぜる試験へ変更した。3秒・Kp12案は実行していない。[数値と保存ログのハッシュ](../evidence/supported-policy-box120-20260929.json)。

| 試験 | 設定 | 結果 |
|---|---|---|
| r1 | 2秒枠、Kp3/Kd0.15、モデル混合率0.5%、最大1°、速度監視0.25rad/s | 推論8回、完了7周期。開始時のID10速度0.264744rad/sで停止。学習目標は未送信。12軸STOP確認、操作者は音声あり・現物異常なし。 |
| r2 | 操作者の希望で5秒枠。速度監視0.35rad/s。減衰を80ms、位置ゲインを400msで滑らかに立ち上げる。他の変位・トルク・20ms出力期限を維持 | 実推論201回、完了200周期（約4秒）。うち180周期で学習目標を送信。完了周期の中央値18.683ms、最大19.348ms。201周期目のID6返信欠落で中断。5秒完走は未達。 |

r2の指令角変化は最大0.1723°、角度読値の変化は最大0.1319°、完了周期の速度読値は最大0.1763rad/s、トルク読値は最大0.0409Nmだった。小動作の試験であり、胴体荷重を支える能力の確認ではない。

ID6は故障値ゼロ・停止モードのフレームをSTOP再送3回とも返したが、直前のType1に未解決の返信が残り、通信に取引番号がないためSTOPへの対応を確定できなかった。曖昧さを消して合格にせず、操作者が40VをOffにし、現物異常なしと報告した。完了した200周期だけを根拠に「5秒・全工程20ms・終了STOP合格」とはしない。

電源再投入後、ID9で生角差+359.9887°が再発した。円周上の差は−0.0113°。生記録を維持し、次回の出力では唯一の角度枝を電源世代と結び直す。

### ソフトウェアの限定変更と検証

- 現起動の501周期無出力診断では定常1周期が20.335ms。CPU優先度−10の比較でも1周期が20.651msで、改善を確認できなかった。
- 支持付きの短時間試験に限定した診断の受入れを追加。診断は最大21ms・100周期当たり超過1回以下・欠落なしを要求し、未達周期をそのまま記録する。これは20ms達成証明ではなく、実出力の20ms返信・鮮度監視は継続する。
- 5秒版は専用設定で選択する。既存の2秒版や現在位置保持版へ、時間延長・速度上限変更を自動適用しない。モデル混合率0.5%、Kp3/Kd0.15、最大1°、推定PD0.1Nm・読値1Nmの上限を維持する。
- 減衰の早期立上げ、途中停止時の連続性、推定トルク超過の拒否、実推論と送信フレームへの反映を含め214テストが通過した。合成試験は物理的な安定性の証拠として扱わない。

20秒・支持台取り外しは未実施。現在の保持力で全重量を支えられる証拠はなく、短時間の通信欠落と終了STOPの未確定も残る。まず支持を残した完走を確認し、荷重を支えられる設定と受けの実物条件を別途確認する。


### r3再試験とSTOP待機延長後のr5

r3は同じ5秒設定で150周期（学習目標130周期）を完了した後、ID8・12の返信待ちで停止した。完了周期の中央値18.692ms、最大19.532ms。終了STOPはID8・12が曖昧で、操作者が40V Off・現物異常なしを確認した。

STOP予算を初回250ms・再送最大500ms・合計1秒へ延長し、上位の回収期限も前後バス共通1.25秒へ修正した。終了ランプの丸め誤差が負の極小ゲインを作る問題も、無次元ランプ値を数学的な範囲0〜1へ収めて修正した。r4キットはファイル検証だけで駆動せず、両修正を含むr5を実行した。

r5は最初の右前ID1の有効化返信が20msに間に合わず、推論0回・学習目標未送信で中断した。前バスのSTOP3回は合計約74msで完了し、全回でID1のmode0・故障ゼロ返信を得たが、有効化返信との対応が曖昧なため未確認を維持。操作者は40V Off・音声あり・現物異常なしと報告した。待機延長が効かなかった理由は合計時間不足ではない。起動時Type3の返信待ちを制御周期から分離する修正を次に検証する。


### 起動時待機を分離したr6

V3の有効化Type3だけ返信予算を30msにし、ゼロゲイン初期化全体を120ms以内へ制限した。有効化・ゼロゲイン返信を各組で確認し、最後に全12軸の新しいmode2返信を得るまで正のゲインを送らない。通常の20ms制御・鮮度監視は維持する。25msの有効化返信を模擬した成功、初期化の累積時間切れでゲインを上げずSTOPするケースを含め、Macの関連273件とJetsonのネイティブ通信54件が成功した。

r6の実機では初期化を59.65msで通過し、実推論32回・完了32周期、そのうち12周期で学習目標を送った。完了周期は中央値18.697ms・最大19.439ms。次の33周期目の入力取得でID12の返信が届かず、書込み後15.636ms待って期限に達した。5秒完走は未達である。

終了STOPは前バス1回・約152ms、後バス3回・約180msで処理を終えた。ID12のmode0・故障ゼロ返信は3回とも観測したが、未解決のType1との対応が曖昧なためSTOP確認へ昇格させなかった。操作者は40V Off・音声あり・現物異常なしを確認。CPU最小周波数設定の復元も成功し、ログはMacへ回収した。

**残件は、待機上限だけでは説明できないCAN/USB返信欠落の切り分け。** 同じ条件の駆動を繰り返さず、次はゼロゲイン通信で送信間隔と同時待ち数を比較し、欠落ID・受信バイト数・期限・USB側記録を同時に評価する。支持台取り外し・荷重移行・自立・歩行は未実施。
