### 残る改善の優先順位

1. 推論入力のテンソル生成（直近で約0.15ms）を保存入力で比較する。再利用する場合も、入力やモデル内部状態の別名参照、型、出力・内部状態・異常入力の拒否が変わらないことを確認する。
2. JSON証跡生成と入力準備をプロファイルする。証跡や入力時刻を省略・改変して短縮扱いにはしない。
3. 改善を確認した候補のみ新しい実入力で反復し、全回20ms未満になるかと、返信までの区間を別々に評価する。

Type2デコード単独は保存入力のJetson CPU計測で中央値5.415µs/回だった。
12回分でも約65µsが元の処理全体の費用であり、この処理だけで0.15ms短縮する案は見送った。
