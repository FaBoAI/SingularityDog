# 固定したIMUを基準にする調整手順

2026-09-22の方針。GY-ICM20948V2は現在の取付位置に固定したまま使用する。取り外しや六面測定を今回の必須作業にしない。**静止基準2収録とジャイロ補正候補を保存し、前側上げ・左側上げの別収録でピッチ／ロールの軸対応と符号が取付変換候補に整合することを確認した。** 後続の旋回収録は再起動後の回収時に要約ファイルが空で、yaw検証には採用していない。[実測結果](hardware-readonly-20260922.md)。厳密な取付角、角度精度、補正の実機適用は未完了。

## 1. 固定する条件

- ユーザー確認：基板のX矢印は犬の左向き、部品面は床側。
- 機体座標：Xは前、Yは左、Zは上。
- 取付変換候補：`R_body_from_sensor = [[0,1,0],[1,0,0],[0,0,-1]]`。装着状態の前側上げ・左側上げでピッチ／ロールの軸対応と符号を照合済み。厳密な取付行列やyawまで検証済みとは扱わない。
- 取付位置・配線を維持し、測定ごとの温度、取得設定、時刻、基準姿勢を残す。基板を再固定した場合は取付方向を再検証する。

「現在の姿勢を基準にする」ことと「機体が水平である」ことは別。水平器などの外部基準で確認していなければ、操作者指定の基準姿勢として保存する。機体の傾斜をソフトウェアだけで水平へ置き換えない。

## 2. 最初に静止基準を取得する

既存の[IMU収録ツール](../runtime/singularitydog_hw/imu_capture.py)で、固定状態のまま整定10秒＋収録30秒を2回行う。1回目を候補作成、2回目を別収録による検算に使う。操作・振動のある区間は基準計算へ混ぜない。温度や平均値が変化し続ける場合は、安定後に別名で取り直す。

以下はリポジトリーの`runtime`からの実行例。Jetson上では、配置済みのソースと実行中の計測プロセスを確認してから実行する。新しい保存先を使い、既存記録は上書きしない。

```sh
python3 -m singularitydog_hw.imu_capture --execute \
  --face unverified --settle-seconds 10 --seconds 30 \
  --output "$HOME/singularitydog-logs/imu-fixed-mount/base-a"

python3 -m singularitydog_hw.imu_capture --execute \
  --face unverified --settle-seconds 10 --seconds 30 \
  --output "$HOME/singularitydog-logs/imu-fixed-mount/base-b"
```

このツールはCANを開かない。IMUの計測用設定は一時的に変更し、終了時に復元する。各`summary.json`の`RECORDED_NOT_CALIBRATED`、`restore_status: restored`、エラーなし、トリム監査の前後一致を確認する。取得周期、欠測、温度、加速度とジャイロの平均・ばらつきも比較する。低いばらつきだけでは一定速度の回転を排除できないため、静止していたという現物確認も記録する。

この2収録は約80秒の計測。位置合わせや通信復旧の時間は含めない。

## 3. 推定するものと、残す未確認項目

| 項目 | 固定状態で行う処理 | 判定の限界 |
|---|---|---|
| ジャイロのゼロ点 | 静止確認したbase-aの平均をbias候補として保存。base-bで差引き後の平均・ばらつきを検算 | 温度・起動ごとに再現性を確認。感度や軸間誤差は未校正 |
| 加速度 | 生の3軸平均、ノルム、基準方向、温度を保存 | 一姿勢では3軸のbiasとscaleを分離できない |
| 基準姿勢 | その姿勢に対する相対変化を診断表示 | 外部基準なしで絶対水平や取付傾きを確定しない |
| 取付方向 | 前側上げ・左側上げの別収録で、固定行列候補のピッチ／ロール対応と符号を照合 | 軸外の動きがあり、厳密な取付角・角度精度・yawは未検証 |

9月22日の機体位置補正**前**の収録では加速度ノルムが約10.7129m/s²、標準重力比で約+9.24%だった。位置補正後の2収録では約+9.045%／+9.097%となり、偏差は残った。前の収録を新しい姿勢の校正として流用せず、補正後の別収録同士で比較している。

全軸へ一律に約0.9154を掛けたり、現在の加速度を丸ごと差し引いたりして「校正完了」としない。加速度には静止時も重力に対応する出力がある。取付方向の回転だけではノルムの偏差は変わらない。

## 4. IMUを外さずに行った軸確認と残る検証

同日、各収録前に40VがOffで機体を支持していることを操作者へ確認し、モーターを駆動せずに前側を上げて戻す収録と、左側を上げて約3秒保持して戻す別収録を行った。IMUは装着したままで、操作者は両方を指示どおり行ったと確認した。最初の収録では左側上げの合図が収録終了後になったため、その記録からロールの確認結果を採っていない。

| 確認した動作 | 収録 | ジャイロの主な応答 | 加速度の照合 |
|---|---|---|---|
| 前側を上げる→戻す | 4,658標本、47.990秒 | 上げる区間でセンサーX負、戻す区間でX正。候補の機体Y負→正に整合 | 上げた区間のセンサーY平均は開始前より約+2.626m/s² |
| 左側を上げる→保持→戻す | 5,347標本、54.990秒 | 上げる区間でセンサーY正、戻す区間でY負。候補の機体X正→負に整合 | 保持区間のセンサーX平均は開始前より約+2.994m/s² |

両収録は生ADCとSI値の換算、取得設定のreadback、トリム前後一致、復元結果、連番、時刻、保存統計の再計算を通過した。動作中のジャイロからbiasを再推定せず、先の静止記録Aだけから求めた候補を診断用に差し引いた。加速度は未補正のまま比較している。

前側上げは開始約18.5〜21.75秒、戻しは約21.75〜23秒に見られた。上げた姿勢でも角速度が残り、明確な静止保持ではない。左側上げは約20.5〜22.75秒、上げた姿勢は約22.75〜25.75秒、戻しは約25.75〜27秒に見られた。こちらも保持中の小さな動きと、主軸以外の回転がある。加速度の変化は符号の補助的な照合であり、外部角度計による角度精度検証ではない。戻した姿勢も開始時と完全には一致しなかった。

これらは候補のピッチ／ロール対応と符号を支持する結果で、六面校正と同等の全軸bias・scale校正や、厳密な取付角の確定ではない。加速度ノルムの約9%偏差、角度精度、yawは残る。

### 後続の旋回収録は不完全な記録として保留

後続の約55秒の旋回収録は、Jetson再起動後の回収時に`summary.json`が0byteだった。`events.jsonl`には5,332標本が残り、JSONの末尾、連番、54.990秒の時刻範囲は整合したが、ソースハッシュ、取得設定readback、前後トリム、復元結果を監査する要約がない。プロセスの終了コード0や標本数の表示だけで完全な収録とは扱わず、要約を作り直して検査へ通すこともしていない。

操作者から「初めは右向きや持ち上げ、最後は左向き」という補足があり、単一の左旋回試験ではなかった。残った信号では約18〜19秒にセンサーZ負の大きな応答、その後約26〜29秒に最後の大きなセンサーZ正の応答がある。候補の`body Z = −sensor Z`では後者は右旋回の符号となり、この区間を「最後の左旋回」とみなすと一致しない。正確な動作時刻が不明なため対応付けは保留し、yaw軸を検証済みにしたり、候補行列を変更したりしない。絶対方位を測った結果でもない。

残る確認には、保存と復元の監査が揃う記録で動作時刻と旋回方向を対応付けること、外部角度基準を使うことが必要。再検証もIMUを装着したまま、40V Offと支持を確認して行い、機体の裏返しは求めない。

## 5. モデルへ渡す前のソフトウェア調整

現在の[保存ログ用の無出力診断](../runtime/singularitydog_hw/policy_shadow.py)は、`−R a / |a|`を重力方向の候補に使っている。加速度の正規化は方向の表現であり、約9%の偏差を修正したことにはならない。生ノルムと偏差の監視を並行して残す。加速度biasがあれば、正規化後にも方向誤差が残る。

今後、検証済みジャイロbiasの差引き、固定した取付変換、時刻付きの連続姿勢推定を接続する。動作中の加速度・振動を静止重力と混同しないよう、加速度の採用条件とフィルターの遅れを測定する。ノルム偏差の許容値を広げるだけで通さず、静止時と動作時を別に検証する。IMUの取付点がモデルの機体原点と離れている場合の回転由来の加速度も、動作時の評価対象に含める。

補正候補は`approved_for_runtime: false`のまま保存し、適用前に別記録で確認する。現在の`imu_capture`は収録機能、`imu_calibration`は六面用であり、固定一姿勢の補正を自動適用するコマンドではない。固定マウントの連続姿勢推定とライブ方策への接続は追加実装・検証が必要。

2収録のオフライン比較には次のツールを使う。静止確認のflagは、操作者が両収録中に機体が静止していたと確認した場合だけ付ける。flagなしなら診断レポートのみ。flagがあっても診断基準を満たさなければ補正候補にしない。加速度bias・scaleや取付回転を推定・適用する機能はない。

```sh
python3 -m singularitydog_hw.imu_fixed_mount_baseline \
  --base-a "$HOME/singularitydog-logs/imu-fixed-mount/base-a" \
  --base-b "$HOME/singularitydog-logs/imu-fixed-mount/base-b" \
  --operator-confirmed-stationary \
  --output "$HOME/singularitydog-logs/imu-fixed-mount/candidate.json"
```

出力はGit外の新規ファイルに限定する。診断のしきい値はレポートに残すが、実機駆動を許可する基準ではない。元ログは変更しない。

候補の効果を保存記録Bで見る場合は、ジャイロだけの相対積分を比較する。元のA/Bを再検査し、Aの平均だけを差し引く。静止確認と診断基準が揃わない記録は拒否する。

```sh
python3 -m singularitydog_hw.imu_orientation_replay \
  --base-a "$HOME/singularitydog-logs/imu-fixed-mount/base-a" \
  --base-b "$HOME/singularitydog-logs/imu-fixed-mount/base-b" \
  --operator-confirmed-stationary \
  --output "$HOME/singularitydog-logs/imu-fixed-mount/replay.json"
```

Hamilton quaternionを`[w,x,y,z]`順で使い、Bの最初のセンサー座標を単位quaternionの基準とする。加速度や磁気による姿勢補正、機体座標への回転、絶対水平への整列はしない。9月22日の約30秒のBでは未補正40.482°、Aのbias候補差引き後0.773°の相対回転となった。静止時の積分ずれの比較であり、実際の機体回転・絶対角度精度・温度変化後の性能を示すものではない。

今回確認できたのは、取り外さず取得した静止基準とその再現性、および別収録によるピッチ／ロールの軸対応と符号の整合。yaw、厳密な取付角・角度精度、無出力の連続推論は残る。これらの診断結果だけで、学習済みモデルの駆動を許可しない。
