# RS05全12台を公式0.5.0.13へ更新 — 2026-09-25

**ID1〜12すべての更新と、更新後の版数・識別・停止状態の照合が完了しました。** 前脚6台・後脚6台ともアプリ版数は `00 05 00 0D`（0.5.0.13）です。全台のSTOP返信がmode0／fault0で、最後の読取り電流も全台0Aでした。モーターのenable・駆動目標・原点／ID変更・工場出荷設定復元・磁気校正は実施していません。

[全12台の検証結果JSON](../evidence/rs05-firmware-update-success-20260925.json)には、転送・返信数、更新後版数、読取り設定の比較、生ログと凍結ソースのSHA-256を収録しています。各台の転送後に全12台を照合し、その結果を確認してから次の1台へ進めました。更新プロセスは全台終了し、ポート閉鎖と排他ロックの解放を確認済みです。

## STARTの応答待ちを修正した根拠

| 試行 | 観測と処置 |
|---|---|
| r2・ID1 | STARTを1回送信し、2秒以内の受信0bytesで中断。INFO／DATA／ENDは未送信。40V再投入後に元の版数・識別・停止を確認 |
| r4・ID1 | 2秒の期限後、50msの静穏確認中に正規START ACKが到着。遅延返信として中断し、START再送とINFO／DATA／ENDは実施せず |
| r5・ID1 | STARTの期限だけ3秒へ変更し、1回のSTARTで全転送と版数確認に成功 |
| r5・ID2の初回 | STARTを1回、3秒待っても無応答。FW本体は送らず中断。40V再投入で復帰を確認 |
| r5・ID2再試行〜ID12 | START完全無応答に限定して最大3回を許可。各台で全転送・更新後照合に成功 |

r4の正規START返信はホストwrite開始から**2,030.555749ms**後でした。この実測を根拠に、r5ではSTARTのACK期限だけを明示的に3秒へ延ばしています。既定値は2秒、INFO／DATA／ENDは引き続き各2秒、転送全体の期限は180秒です。3秒は今回の観測に基づく設定で、メーカーが全個体へ保証した応答時間ではありません。モーター内部・USB基板・ホストの遅延の内訳は未分離です。

部分write、受信があるのに成立しないACK、遅延／不正／重複返信、非ゼロ状態、切断、起動ID変化、取消、全体期限超過では中断します。受信を捨てて再送可能と扱う処理はありません。OTA開始後の失敗では追加のSTOPや設定命令を送らず、記録を保存してポートを閉じます。[更新ツールの説明](../runtime/FIRMWARE_UPDATE.md)

## 更新前後の照合

最終値は、同じJetson起動中のr5開始前バックアップと比較しました。

| 項目 | 全12台の最終結果 |
|---|---|
| UID／CAN ID | 既知の同一個体・割当と一致 |
| アプリ版数 | 0.5.0.9 → 0.5.0.13 |
| `run_mode` `0x7005` | 全台0 → 0 |
| CANタイムアウト `0x7028` | 全台0 → 0 |
| ゼロ状態 `0x7029` | 全台0 → 0 |
| 位置 `0x7019` | 更新前との絶対差は最大約0.008524° |
| 電流 `0x701A` | 最終読取りは全台0A |
| 電圧 `0x701C` | 個体の報告値36.81〜38.11V、全台が試験下限35V以上 |
| STOP返信 | 全台mode0／fault0 |
| 通信終了 | 受信静穏の成功記録、解析後の残留0bytes、ポート閉鎖・ロック解放を照合 |

[バックアップ](../runtime/singularitydog_hw/firmware_backup.py)は上記に速度 `0x701B` を含めた既知7項目の読取りです。`run_mode` は制御モードの列挙値であり、停止はSTOP返信から別途確認しています。生ログにはデータのないread呼出しの時刻をすべて記録していないため、静穏区間は保存された成功フラグと解析残留0の範囲で確認しています。

**既知設定3項目の一致と小さな位置差は、全NVMや機械ゼロ・磁気校正の完全保持を保証しません。** 外部の関節校正候補は保存済みですが、今回のFW更新で承認・書換えはしていません。ID1は途中の40V再投入後も0.5.0.13を確認しました。全12台を揃えて手動電源再投入した後の再確認は今回の最終判定には含めていません。
