# RS05公式FW 0.5.0.13：r2初回のID1試行と復旧 — 2026-09-25

**この文書はr2初回試行の記録です。後続のr5では全12台を0.5.0.13へ更新し、版数・UID一致・STOP返信mode0／fault0を確認しました。** 最新結果は[更新成功記録](rs05-firmware-update-success-20260925.md)と[結果JSON](../evidence/rs05-firmware-update-success-20260925.json)を参照してください。Active Reporting・20ms制御・全NVM保持の検証は完了していません。

**r2の結果：更新未完了。** ID1への更新開始命令に2秒以内の応答がなく、FW本体は送信せず中断しました。電源再投入後、全12台が元の0.5.0.9で応答し、停止状態mode0・fault0を確認しました。

ホストwrite完了はCAN線上での到達証明ではありません。r2の2秒待機内にはSTARTへの応答がなく、更新待ち状態への移行自体も未確認でした。この初回試行後のアプリ版数は0.5.0.9で、r2による0.5.0.13への更新は成立していません。

## 保存した範囲

バックアップした値は、`run_mode 0x7005`、位置`0x7019`、電流`0x701A`、速度`0x701B`、電圧`0x701C`、CANタイムアウト`0x7028`、ゼロ状態`0x7029`です。`run_mode`は制御モードであり、励磁状態の証明には停止返信を別途使います。ゼロ状態の列挙値は、機械ゼロ・オフセットの完全なNVMバックアップではありません。未読取の設定が保持されたとは主張しません。

外部の関節校正ファイルは既存の**未承認候補**をそのまま保存しました。今回の更新試行で校正を承認・変更していません。モーターの有効化、目標角送信、ID変更、原点変更、初期化、磁気／コギング校正は行っていません。

個体UID・生ログ・接続情報は非公開で保存し、公開用には[結果JSON](../evidence/rs05-firmware-update-attempt-20260925.json)へ集計値と証跡ハッシュを記録しました。

## r2時点の実装と検証

以下は初回試行時点の構成です。コードのリンク先は現行版のため、後続版のSTART限定再試行・期限変更については成功記録を参照してください。

- [バックアップ](../runtime/singularitydog_hw/firmware_backup.py)：Type0／17のみ。全12台の既知UID、起動ID、安定したUSBパスを検査し、要求を1つずつ送信。
- [転送状態機械](../runtime/singularitydog_hw/rs05_firmware_transfer.py)：公式BINのサイズ・ハッシュを固定。Type11→12→13×11,698→14の成功経路だけを許可し、異なる応答・非ゼロ状態・欠測・期限切れで中断。
- [実機ラッパー](../runtime/singularitydog_hw/rs05_firmware_update.py)：既定は実行計画表示。新しい完全な事前記録、1台の明示指定、ポートの排他所有が必要。OTA中断時の制御命令送信を禁止。

ローカル全体921テスト、最終ラッパー修正後の関連9テスト、転送したr2のJetson上200テストが成功しました。これらはr2時点の検証記録で、初回の実機試行はSTARTで中断しました。

## r2終了時点の切り分けと後続試行への条件

STARTの29bit CAN IDとAT符号化を、[公式CAN-USB変換コード](https://github.com/RobStride/CAN-USB-data-conversion/blob/72524311fbf4980d74ad53387c075cc50d8dd417/switch/mainwindow.cpp#L100-L156)と独立照合し、不一致はありませんでした。UIDも更新前記録のID1と照合済みです。ただしCAN線を直接観測していないため、アダプターからの送出、モーター側の処理、返信の経路のどこで止まったかは未確定です。

[公式Python](https://github.com/RobStride/Product_Information/blob/6ad12f50006273b7ea4eea88980f927d97c22f0d/OTA/OTA.py)には最大3回の汎用再試行がありますが、「最初のSTARTは無応答になる」という保証は見つかっていません。[RS05マニュアル](https://github.com/RobStride/Product_Information/blob/0f4ad74fdb67023e75bbcbeebecd6f1a003ce000/Product%20Literature/RS05/RS05User%20Manual260713.pdf)のGUI上の2段階開始も、Type11を2回送るという仕様ではありません。r2ではこれらだけを理由に再送せず終了しました。

r2終了時点では、開始条件の追加確認、公式GUI／SocketCAN経路、受動CAN観測を次の切り分け候補としていました。その後、明示された再試行でr4のSTART返信が約2.031秒後に観測され、r5でSTARTの期限だけを3秒へ変更しました。限定した再試行条件と実測結果は[成功記録](rs05-firmware-update-success-20260925.md)に残しています。メーカーへの問い合わせ文は[準備文書](rs05-firmware-0.5.0.13-update-20260925.md)にあり、未送信です。

後続試行ではID1の転送・版数0.5.0.13・識別・停止・限定設定／角度比較が成立してから、残りも1台ずつ更新しました。FW更新後のActive Reporting回帰試験と全工程20ms検証は未実施です。既知項目の一致を全NVM保持の証明には拡張しません。
