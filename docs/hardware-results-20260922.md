# 2026-09-22：右前脚の小角度試験と左前脚の開始前中断

右前脚3関節へ相対5°を指令する5秒の試験を1回実施し、全3関節の停止応答を確認しました。操作者は「動きが見えた。異常なし」と確認しています。支持台上の低ゲイン試験で、体重を支える起立や学習済みモデルの出力はまだ試していません。

## 指令と実際の動き

13:14 JST、右前脚の足先側からID 1・2・3へ、現在値を基準にraw角度の正方向へ各5°を指令しました。4秒で徐々に動かし、端点で1秒後に停止しています。Kp=3、Kd=0.15、フィードフォワード=0、制御周期50msです。

| ID・部位 | 指令変化 | 最後に観測した変化 | 指令との差 | 最終停止応答 |
|---|---:|---:|---:|---|
| 1・足先側 | +5° | +4.575° | -0.425° | reset 0 / fault 0 |
| 2・中央 | +5° | +3.697° | -1.303° | reset 0 / fault 0 |
| 3・付け根 | +5° | +1.245° | -3.755° | reset 0 / fault 0 |

**付け根の追従は約1.25°に留まりました。** 動きと停止を確認した成果と、目標角度へ到達できなかった課題を分けて扱います。この結果だけで保持力を判断したり、ゲインを上げて起立を実施したりはしません。

## 記録の確認

転送10ファイルのSHAを照合し、前492・試験411・後252の送受信フレームを独立に再構成しました。欠落・余剰はなく、全12個体の識別情報が前後で一致。FR3個体のenable、300本の正ゲイン指令、最終3停止を確認しています。前後の取得電流は全12個体で0Aでした。

ID1の静止時速度RMSは0.05456rad/sで旧0.05rad/s閾値を超えましたが、既に用意したFR専用position-v2の位置変動・末尾安定・符号付き平均の条件を満たしていました。試験後に基準を緩和したものではありません。

ウォッチドッグ200ms相当の設定値は読戻しまでで、通信断時の物理停止遅延は未測定です。また、公式資料間の速度・トルク換算範囲の差が未解決のため、表示トルクを校正済みの実トルクや上限制限の証拠にはしません。

## 起立までに残る点

右後脚の付け根について、旧原点と目視基準の差を回転中心の図で照合しています。次に必要なのは基準の再現性、残りの脚の動作確認、全12関節の停止と支持姿勢への移行、荷重をかける前の保持設定です。[全体の段取り](deployment-roadmap-20260922.md)に通信20ms・IMU・無出力推論の条件もまとめています。

写真・生ログ・個体識別番号・接続情報・学習済み重みは、この集計に含めていません。

## 右後脚の基準位置を2回照合

その後、操作者がID9とID8の回転中心を胴体の左右方向と平行に合わせ、一度離して同じ位置へ戻した2記録を取得しました。同一のJetson起動中・同一個体で、各10標本・492送受信フレームに欠落はありません。ID9の戻し差は平均−0.038553°、中央値−0.056714°でした。

2記録それぞれの中央値を等重みで平均し、モデルhip=0の仮定に対応するソフト側補正候補を保存しました。既存の符号+1を維持すると、`q_model = raw + 0.687396377325058`（rad、折返しなし）。旧候補のoffsetから+34.908171°の変更に相当します。元の校正ファイル、制御設定、モーター内の原点は変更していません。

これは目視による基準の再現性です。絶対角度の測定や、回転方向・電源再投入後の継続性の再検証ではありません。戻し記録には速度最大0.128051rad/sのヒューリスティック警告もあり、駆動前の静止判定合格とは扱いません。4脚すべての校正を繰り返す前に、右後のこの候補を無出力で比較します。

## 充電後の左前脚試験はenable前に中断

左前脚は当初、ID6の電圧34.844Vが35Vの試験下限を下回り、実行を保留しました。操作者の充電・再投入後、全12台の個体照合と37.581〜38.914Vを確認。13:56 JSTに左前脚ID4・5・6の相対−5°・5秒試験を開始しましたが、ID6の`can_timeout`（0x7028）読出しがstatus1となり、**enable・正ゲイン指令を送る前に中断**しました。動作成功には数えません。

初期停止とゼロゲイン3指令の後、ID4・5へ200ms相当の揮発設定を書き、ID6の旧値読出しで中断しています。最終的に3台ともreset0・fault0の停止応答を確認。後続の全12台読出しで電流0Aを取得しました。ID4・5の設定値4000は追加読出しで確認していますが、通信断時の物理停止時間は未検証です。

設定値の一括読出しでは、**ID6・9・10だけがstatus1、残り9台はstatus0**でした。これは[9月20日の診断](hardware-bringup-20260920.md#実測で残った課題)と同じ個体群です。公式の意味は「読み出し失敗」であり、未対応・FW差・故障のどれかはまだ確定していません。通常の位置・電流・電圧を取得できても、必要な通信タイムアウト設定の確認を省略しません。

今後、同じ問題で設定が途中まで変更されないよう、試験コードは3台すべての旧設定を読んでから一括して書く順序へ修正しました。第3台が拒否した場合に設定書込み・enableを送らず全台停止する回帰テストを追加し、関連63件が通過。今回の実機中断は修正前r21による記録で、この修正後の実機試験は未実施です。続く全12台の版数照会で差を確認しました（下記）。

## 保存データで実機準備を自動判定

`prestand_check`と`policy_observer_replay`をJetsonへ配置し、保存済みデータでMac側と同じ判定を確認しました。デバイスやモーターへ出力するツールではありません。

- 充電後の電圧・電流は全12台で基準内。脱力姿勢を元の校正候補で変換すると、付け根ID3・6・9・12はモデル角度範囲外でした。姿勢移行と校正候補の照合が必要で、範囲内へ数値を切り詰めていません。
- 完了したCAN＋IMU収録を元の時刻のまま再生すると、最初のtickで観測年齢／取得幅が148.438491msとなり、指定した診断上限100msを超過。h=0/1とも推論前に停止し、実データで完了した方策tickは0です。

合成入力による状態保持推論の成功と、実データの時刻条件による停止を分けて記録します。新しい2ツールを含め、ライブ50Hzや荷重起立が成立した結果ではありません。[無出力診断の使い方](../runtime/POLICY_OBSERVER.md)

## 全12台のバージョン照会

14:18 JST、全12台が応答。ID6・9・10は0.5.0.3、ほか9台は0.5.0.9でした。古い3台はタイムアウト設定の読取失敗個体と一致しています。全台の個体照合と停止応答を確認し、enable・設定変更・ファームウェア書込みは行っていません。最新版は公式0.5.0.14ですが、更新前後の比較は未実施です。[ID別の一覧と根拠](motor-firmware-inventory-20260922.md)。
