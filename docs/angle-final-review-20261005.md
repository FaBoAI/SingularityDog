# 10月5日・12軸の最終角度校正を詰める手順

追加確認したID4・5・10は、相対回転の方向と復帰が既存の候補判定を通った。ID5は新しい起動・seedへ結び直したr10で、回転＋16.322°、復帰差＋2.322°、他軸の移動最大0.692°。全38ファイルと4収録のCAN生bytesを独立検算し、操作者は音声・床への復帰・異常なしを確認した。絶対原点の誤差と静止速度の原因は未確定であり、正式な校正・実出力の承認とは分ける。

既存の水準器L字は4脚それぞれの3軸原点として再利用する。9月28日の原記録は、気泡水準器の器差と機構へ当てる面の誤差を数値化しておらず、12軸すべての絶対誤差が未確定。最新のr64最終offsetはその水準器原点を保持している。ID10は後続の相対出力軸回転から符号−1を保持する。古いカメラL字だけの原点へ戻さない。

追加するのは不足した証拠だけとする。取付・個体が変わっていない軸の原点を全数取り直す必要はない。

| 確認 | 再利用するもの | 不足する最小記録 |

## 保存読値から外部角度の入力表を作る

新しい通信や駆動を追加しない。既存の `motor_epoch_readonly_capture` で保存した「基準・回転後・復帰」のJSONを使う。全12軸captureから不足軸だけを選べる。以下はID4の例で、パスはGit外の非公開ディレクトリーとし、出力名は毎回新しくする。

```bash
PYTHONPATH=runtime:. python3 tools/audit_angle_calibration.py \
  --profile "$DOG_ANGLE_PROFILE" --capture "$DOG_REFERENCE_BASE" \
  --reference-capture "$DOG_REFERENCE_MOVED" \
  --reference-capture "$DOG_REFERENCE_RETURN" \
  --reference-id 4 \
  --reference-template-output "$DOG_REFERENCE_TEMPLATE" \
  --output "$DOG_REFERENCE_TEMPLATE_AUDIT"
```

複数軸は `--reference-id` を繰り返す。全軸を処理するときだけ省略する。同一captureの重複、個体・起動・記載電源世代の変更を拒否する。入力表には生角・UID・元captureのSHA-256を転記し、外部角度・誤差・相対軸観察・測定方法は `null` のまま残す。

各行の `model_rad`、`uncertainty_rad`、`relative_output_shaft_observed`、`physical_angle_method` を実際の計測から記入する。角度と誤差はrad、方法は `angle_gauge` / `fixture` / `calibrated_image` / `visual_bounded`。外部計測を記録した別ファイルも保管し、原captureのSHA-256を変更しない。`motor_power_epoch` が未確定の記載なら、保存した操作者電源イベントと既存manifestに照らして同一世代を確認してから記入する。bootだけを電源世代にしない。

```bash
PYTHONPATH=runtime:. python3 tools/audit_angle_calibration.py \
  --profile "$DOG_ANGLE_PROFILE" --capture "$DOG_CURRENT_CAPTURE" \
  --references "$DOG_REFERENCE_TEMPLATE" --output "$DOG_FINAL_ANGLE_AUDIT"
```

`reference_fits_by_id` に符号、offset区間、外部計測誤差、残差、実角・生角の変化量比を保存する。fit区間が一点に縮んでも `uncertainty_rad` は入力した最大計測誤差を下回らない。変化量比は固定の単位尺度を仮定した整合診断であり、動的Type2校正の完了ではない。

`batch_review_plan` の `external_reference_remeasure_ids` と `external_reference_sign_conflict_ids` から該当軸だけを再確認する。成功したfitはレビュー候補であり、profileへ自動適用しない。最終の原点・符号・非ゼロ誤差・物理範囲は、既存profileとhardware reviewへ正確に反映し、設定・モデル・元記録のハッシュを固定する。`prepare_supported_profile.py` と既存の正式試験判定を使い、別の出力許可を作らない。

### ID5の静止速度：200msと20msの実機読取りを比較

操作者の箱支持・脱力・手離し・即時Off・他の駆動ツール停止の回答を記録し、凍結r4キットを変更せず、別の読取りaddonと私有入口を配置した。全12 UIDを確認後、ID5だけを位置→速度→位置の順で200ms間隔、続いて20ms間隔で各約10秒取得した。同一起動、区間と生ログの非重複、ソース5ファイルの一致を検算した。回答「OK」から個別の電源操作履歴や電源世代の継続は推定せず、未確認のまま保持する。
