# 2026-09-23 実機作業の手順と時間目安

作成：2026-09-22。時刻指定がないため開始からの所要時間で記載。QDD交換と必要なソフトの準備が完了している場合の作業見積りで、実測所要時間ではありません。

**最初の約60分で、交換した3台の確認・校正と残り3脚の動作・停止確認を目指します。全軸の停止検証と支持付き四足起立まで進める場合は、条件が揃えば合計約90〜120分。学習済みモデルの実駆動には未完成の通信・制御処理があり、同じ時間枠での完了は約束しません。**

## 9月23日午前の更新と次の順序

交換したID6・9・10の識別・版数照合、校正候補の再記録、FL/RR/RL各3関節の5°・5秒試験を完了。3脚とも停止応答と操作者の異常なしを確認した。9月22日のFR試験と合わせ、4脚それぞれの限定動作を確認できた。全12軸同時の駆動・起立確認ではない。数値は[交換後の実測結果](hardware-replacement-check-20260923.md)へ記録する。

次は既に終えた脚別確認を繰り返さず、以下の順に進める。

1. **保持の実装と計測**：付け根は5°指令に対する実変化がFL約0.81°、RR約3.25°、RL約0.63°。負荷方向・電流／トルク・追従誤差を同時に記録できる有限の保持処理を用意する。保持後の脱力で姿勢が変わる点を、駆動中の追従と分ける。
2. **開始姿勢の扱い**：最後の停止後記録では、校正候補で変換したID3・6・9がモデルの付け根範囲外。基準の再現性と機械的可動域を照合し、開始姿勢から目標への移行を設計する。値を切り詰めたり角度を自動で折り返したりしない。
3. **全12軸の有限移行・停止処理**：脚単位ランナーをそのまま拡大せず、12軸分の送受信時間、観測の古さ、異常時の全対象停止、watchdog実停止時間を測る。ここまで検証してから支持付き四足保持へ進む。
4. **方策入力の周期検証**：ライブ無出力ツールを実装済み。初回実測では全12台の識別とCAN・IMU取得まで到達したが、最初の20ms tick開始期限を超えて中断（予定tickから例外記録まで35.23ms）。実センサーによる推論は0回。初期化と周期開始を分離した再測定では初回開始遅延0.220659msで期限内になったが、関節角がモデル範囲外のためforward前に中断。継続周期の検証は残る。100msの入力鮮度条件は診断用であり、学習時20ms駆動の許可ではない。

watchdog4000の書込み・読戻しは当日のFL/RR/RL各3台で確認した。物理的な通信断停止時間は未測定。下記の前日作成見積りは履歴として保持し、実施済み項目と混同しない。11時までの歩行完了には到達しておらず、残る実装・検証を省略して方策を出力しない。

合計の目安は40〜58分で、約60分の作業枠とします。支持・即時Offは冒頭にまとめて確認し、状態変更がなければ同じ質問を繰り返しません。4脚同時にL字を保持する必要はありません。

既存の `~/calibrate-dog --leg FL`、`--leg RR`、`--leg RL` は脚全体を記録します。交換関節だけを選ぶコマンドは現時点で用意されていません。記録しただけで新校正が自動採用されるわけでもありません。交換しなかった関節の候補は、組付けを変えていなければ既存記録を保持し、必要な照合だけ追加します。

エラーが出た場合は該当箇所だけ切り分け、原因を変えずに同じ試験を繰り返しません。機械的な抵抗・異音・予期しない動きや通信異常があれば、その段階で止めて結果と残作業を表示します。

## 追加30〜50分：全軸の停止検証と支持付き四足起立

開始条件：12軸の個体・符号・原点・可動域、停止処理の実装、出力制限、IMUの傾き監視、起立軌道専用の周期と観測鮮度を検証済み。脱力姿勢で範囲外となった付け根ID3・6・9・12の対応も整理する。交換3台だけの校正で自動的に起立条件が揃うとはしません。

全12軸の停止経路と通信断時の物理停止を、事前に定めた測定方法・判定値でまず確認します（追加10〜20分の枠）。設定値4000の読戻しだけでは実停止時間を確認したことになりません。次の姿勢移行・保持は、この確認後に20〜30分の枠で進めます。

1. 脚を浮かせたまま、現在姿勢から小さい連続変位で四足立位の脚形へ移す。未到達や引っ掛かりを確認する。
2. 全対象の停止を確認してから、足を接地させ、胴体の荷重を補助できる支持へ切り替える。
3. 荷重を補助しながら短い保持を測定し、支持状態を確認して終了・脱力する。

目標は犬のような四足姿勢の保持です。今日の5°試験で付け根が約1.25°しか追従しなかった点を踏まえ、目標未到達を現場の急なゲイン増加だけで解決しません。低頻度の固定姿勢制御を別途検証できれば、方策用50Hzの完成より先に取り組めます。FR用20Hz試験を全12軸へ単純拡張する意味ではありません。

段取りの余裕を含め、ここまで条件どおり進めば開始からおよそ90〜120分が目安です。全12軸ランナーが未完成の場合は、脚別の確認結果までをその日の成果として保存し、ソフトの準備を続けます。

## 学習済みモデルのテスト：準備完了後に追加30〜60分

現時点で時間を約束できない主要因は次の3点です。

- 12軸読出しの最短実測は26.64ms。学習時の20ms周期へ未到達。CAN 1MbpsとUART 921600bpsを区別し、送受信・IMU・推論を含めて周期と古さを測る。
- 実収録の保存ログ再生は取得幅148.44msで最初のtickから停止した。合成入力の成功は、実センサー50Hzの成功ではない。
- 学習時の駆動制限・内部状態とRS05内部制御、全12軸の制限・停止・姿勢移行の接続が未完了。

準備後は、実センサーを使う無出力推論→限定出力の経路確認→足接地・荷重補助下の短時間方策試験の順。実行時間は2秒→5秒→10秒を候補に、各試験の測定結果から延長を判断します。これらの時間は準備後の試験案で、現在の実行可能設定ではありません。

初回は第28回Aの配置済み候補を使います。新しい挨拶候補への差し替え、40cm/sへの加速、伏せ・挨拶・お座りの切替はこの枠へ混ぜません。低速指令を使う場合も、その条件で事前評価した値を用います。

## 明日の成果を短く判定する

- 第1目標：交換3台の識別・版数・校正を確定し、残り3脚の動きと停止を確認。
- 第2目標：全12軸の条件が揃えば、支持付き四足立位と保持・終了を確認。
- 第3目標：通信と駆動の事前検証が通れば、学習済みモデルの短時間実機テスト。

全台FW更新は、交換後の実際の版数と動作対応を見て別枠で扱います。WindowsなしでのOTAには資料と実装の照合が残っており、根拠が未確定の書込みを試験時間へ組み込みません。終了時は到達段階、未達理由、次に必要な1作業を記録します。
