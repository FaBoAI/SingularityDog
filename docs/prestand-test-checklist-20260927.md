A〜Dの現場枠は**約43〜85分**。これは充電・再接続・固定具改修・失敗区間の修正、後脚付け根9/12の2軸ランナー開発を含まない。従来の「1関節ずつ準備と5秒保持を繰り返す」工程をAとDへ集約し、前脚付け根はBの同一Enable内で5°と10°を判定する。ただし、BとDを同一Enableでつなぐことや、STOP後に経路確認なしで次の組を動かすことは現在の実装にはない。Eまで含む固定立位の見積もりは[短縮手順](fast-track-standing-20260927.md)も参照する。

AでFW版数は保持ツールのreviewにある既存記録とUIDの対応を照合する。**この保持ツールは毎回ライブFW版数を再照会しない**ため、版数が疑わしい個体のライブ照会は別作業とし、保持ログだけで「最新版を実測確認」とは記録しない。IMUも保持ツール自身の出力ではない。

学習済み方策で立たせる前には、固定立位に加えて実入力74観測とIMU/関節角の符号・単位を確認し、実入力→推論→**実目標送信**の1,500周期を20 ms以内・欠測/期限超過なしで測る必要がある。現在の20 ms前後の測定はSTOP代理送信による短い試行で、連続駆動の合格ではない。支持台を残したまま方策の最初の目標差と切替を検査し、それから荷重移行と歩行を別々に試す。

Bの準備・証拠取込には[セッションCLI](front-hip-test-session-20260927.md)を使う。失敗時はログを保存し、同じ未確認経路へ自動で再指令せず、失敗した区間だけ直す。

同一起動のA・Bの証拠は、Macに保存したセッションから次の**読み取り専用**コマンドでまとめて確認する。全12軸保持に含まれるUID・電圧・故障・初回/終了STOPを再利用し、前脚付け根の無駆動preflight・物理レビュー済みパッケージ・5°→10°実行結果を区別して表示する。`MISSING`は未収集、`FAIL`はログの不一致または失敗を示す。この表示はIMU、現物の干渉、Dの関節組、固定立位の合否を代行しない。

```sh
python3 -B tools/prestand_batch_status.py --session "$SESSION" --table
```
